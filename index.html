The problem

The dark matter of data

Most of the world's information lives in binary formats — scientific datasets, satellite imagery, media, network captures. It's opaque, locked behind specialized parsers, and its meaning is buried in proprietary or poorly-documented specs.

Opaque by default

A wall of bytes tells you nothing. Without the right software and tribal knowledge, the structure and meaning stay invisible.

Brittle, hand-written parsers

Every format needs bespoke code in every language. It's error-prone, hard to validate, and expensive to maintain.

No shared meaning

A width in a PNG and a width in a JPEG are the same concept — but nothing connects them. Cross-format analysis is impossible.

How it works

Three layers, one meaning

Instead of one monolithic spec, Hexplain separates concerns into interoperable ontologies. A conforming processor turns a binary stream plus its description into a formal RDF instance graph — not just parser instructions, but queryable knowledge.

Physical
The sequence, structure, and data types of the bytes themselves.
Layout
How multi-dimensional data is organized within a flat byte stream.
Semantic
The conceptual meaning — mapped to shared, cross-format vocabulary.
Open by design

Built on the standards you already trust

RDF OWL SHACL JSON-LD SPARQL

Domain vocabularies align to Dublin Core, the W3C Ontology for Media Resources, SOSA/SSN, and GeoSPARQL — so your descriptions plug straight into the wider linked-data world.

See it in action

Map a field once. Query every format.

Describe where a value lives in the bytes and what it means. Then ask questions across your whole corpus — without knowing whether each file is a PNG, a JPEG, or something you've never seen.

png-profile.ttldescription
# The PNG IHDR width field, mapped to a shared concept
:IHDR_Width a bddo:Field ;
    bddo:hasDataType bddo:uint32 ;
    bddo:byteOrder  bddo:BigEndian ;
    bddo:atOffset   16 ;
    hexplain:mapsToProperty img:width .

# A JPEG description maps its SOF0 width
# to the very same img:width property.
query.rqSPARQL
# Every large image — regardless of file format
PREFIX img: <https://hexplain.io/ns/image#>

SELECT ?file ?w WHERE {
  ?file a img:Image ;
        img:width ?w .
  FILTER(?w > 4000)
}
ORDER BY DESC(?w)

No more hunting for the width field's offset and data type in a dozen format specs. The meaning is explicit, and the query is portable.

How it compares

Others stop at the parse. Hexplain keeps going — to meaning.

Declarative binary-description tools solve half the problem: they turn bytes into fields. Hexplain adds the layer none of them have — a shared semantic model that makes the data queryable, validatable, and interoperable across every format.

Kaitai Struct is excellent at generating parsers, DFDL is a solid XML-oriented standard, and Protobuf and Avro are great for defining new formats. Hexplain is the only one that turns any binary into linked data you can reason over — and it can complement the others rather than replace them.

Modular by design

The Hexplain ontology family

A small foundation, a set of domain vocabularies, and cross-cutting aspects — each a versioned module with its own spec. Compose only what you need.

Foundation
bddo

BDDO

The physical layer: structs, fields, primitive types, endianness, bitfields, arrays, checksums, and control flow.

 hexplain

Core

The glue that links physical structure to semantic meaning and layout — mapsToClass, mapsToProperty.

 dlv

DLV

Data Layout Vocabulary: dimensions, axes, and interleaving (BIL / BIP / BSQ) for scientific and geospatial rasters.

 hel

HEL

The Hexplain Expression Language for conditions and calculations: dynamic sizing, presence, counts, offsets, dispatch.

 processing

Processing Model

The normative execution model: how a processor turns bytes + description into an RDF instance graph, with IRI minting.

 architecture

Aspect Architecture

Cross-cutting aspects — color, time, encoding, geometry, provenance — each concept defined once, imported everywhere.
Domain vocabularies
img

IDV · Image

Pixel width, colour space, compression.

 vdv

VDV · Video

Frame rate, codec, resolution, duration.

 adv

ADV · Audio

Sample rate, bit depth, artist, album.

 gv

GV · Geospatial

Coordinate systems, projections, sensors.

 dfv

DFV · Doc & Font

Page count, author, font family.

 npv

NPV · Network

Source address, destination port.

 axv

AXV · Archive

File name, checksum, modification time.

What you can build

An executable spec powers real tools

Because Hexplain descriptions are formal and machine-readable, a single description drives an entire ecosystem — no more re-implementing the same format five times.

Parser & codec generators

Generate high-performance parsers and writers in Python, C++, or Rust straight from a description — no manual, error-prone code.

Conformance test suites

Use a description as ground truth to validate a corpus of files for structural integrity, correct values, and conditional logic.

Semantic query engines

Ingest heterogeneous binaries plus descriptions into one knowledge graph and run high-level SPARQL across the whole dataset.

Semantic hex editors

Show a structured, hierarchical, semantically-named view of a file — meaningful fields instead of a raw wall of bytes.

Format converters

Two descriptions and their shared semantic mappings let tools translate data between formats while preserving meaning.

Long-term preservation

A description is enduring, self-contained documentation — guaranteeing data can be understood long after its software is gone.

In the field

Where Hexplain earns its keep

Geointelligence

One query across every imagery format

Describe GeoTIFF, NITF, and HDF5 against the Geospatial Vocabulary, then run a single query: "all WorldView-3 datasets collected after Jan 2024 that contain a Lidar point cloud" — via gv:platformName and gv:PointCloud.

Digital forensics

Automated file carving & extraction

Scan a raw disk image for signatures with bddo:syncOnMarker, parse each file, validate integrity via declared bddo:Checksums, and pull key metadata like EXIF camera model — automatically.

Broadcast media

Automated QC at ingest

Parse incoming MXF and MOV files to the Video Vocabulary, then flag anything where vdv:frameRate isn't 29.97 fps or vdv:audioChannels isn't 2 — no manual inspection.

Format conformance

A testable spec, not a PDF

Publish an official Hexplain Profile for "FormatX 2.0" as a definitive, machine-readable reference — and build a conformance suite that validates real sample files against it.
