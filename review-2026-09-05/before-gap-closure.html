The reference now covers 731 resources, 93 named shapes and 35 modules. These are documentation counts. The 246-entry GDAL inventory is a documentation/coverage inventory, not a count of supported binary decoders.

Specification 8.75/10

A well-documented, layered working specification with stronger numeric constraints. The main gap is independently verified format interoperability and competency evidence across the full vocabulary.

SP01 · High · Fixed

Finite-value constraints accepted infinity under another spelling

A calibration literal "1e309"^^xsd:double passed the lexical blacklist although its numeric value is infinite. This can contaminate georeferencing or calibrated values.

Evidence: Both positive and negative overflow spellings passed before the fix. Nine pySHACL boundary cases now pass; Jena independently verifies nonfinite rejection and finite extremes.

Action / next step: Added numeric bounds excluding both infinities while preserving valid finite extremes and signed zero. No-data NaN remains allowed in its separate contract.

SP02 · High · Fixed

Band-index uniqueness confused RDF identity with numeric equality

Two bands could both occupy numeric index 1 when one index was xsd:integer and the other xsd:unsignedInt.

Evidence: The counterexample conformed before correction. It now fails in pySHACL and Jena.

Action / next step: Join the two index values independently and compare them numerically. Band resources themselves are compared by RDF term identity.

SP03 · High · Fixed

Malformed coefficient lists hid duplicate equal-valued literals

Two different lexical double literals with equal numeric value could both be rdf:first on one coefficient cell. The list was not well formed, yet value inequality failed to detect it.

Evidence: A valid 20-cell vector passes; adding a second equal-valued but distinct rdf:first now fails. Repeated values in separate cells remain legal.

Action / next step: Use sameTerm for list multiplicity checks in raster and spatial-reference constraints. Numeric equality remains appropriate for quantities, not graph cardinality.

Engine 7.65/10

A capable parser/compiler with much stronger boundary handling. General writer symmetry, complete layout support and whole-parse execution budgets remain substantial limits.

EN01 · High · Fixed

Sizes and repeat counts narrowed before validation

A fixed size of 4,294,967,297 bytes wrapped to one byte. Fractional counts were truncated, and a large count could trigger a large allocation before reading input.

Evidence: The fixed-size and count counterexamples failed the new expected-correctness tests before this pass. Exact conversion and uint64/count tests now pass.

Action / next step: Validate integral finite values before narrowing; bound byte/string allocations by remaining input; start repetition storage with a modest capacity. Existing recovery semantics are retained.

EN02 · High · Fixed

Array access could return wrong signed values or aliased cells

Signed -1 decoded as 255; uint32/uint64 values narrowed silently. Missing/extra indices, invalid logical coordinates and overflowing strides could access an unrelated byte.

Evidence: Pre-fix tests reproduced signedness, index and stride failures. Final tests cover uint64 maximum, float64 precision, bounds, rank and truncated cells.

Action / next step: Added exact getInteger/getLong and getDouble accessors. Narrowing getInt fails outside its range. Checked long arithmetic and complete-cell bounds protect every array access.

EN03 · High · Fixed

Inflater termination could mean partial success or endless waiting

A truncated compressed block returned partial data; a preset-dictionary request could repeatedly make no progress. Native resources were not released on every failure path.

Evidence: Every truncated prefix of sample zlib/raw DEFLATE payloads is now rejected. Dictionary, empty-stream, output-budget and trailing-byte cases pass.

Action / next step: Require stream completion, fail on missing dictionaries or stalled progress, and release native resources in finally. Correct RFC 1951 and Deflate dispatch to raw framing.

Unsigned 64-bit output became zero

Evidence: The uint64 maximum now survives parse/write exactly. Fractional, nonfinite, nonnumeric, negative unsigned and overflowing integer values are rejected.

EN06 · High · Scoped mitigation

Decoded-byte limits do not bound a whole parse

A small compressed input can create a large result. Multiple blocks, recursive structures or zero-byte repetitions can still consume excessive total memory or CPU.

Evidence: All built-in codecs enforce configurable per-block output limits; the core default is 64 MiB. Tests use small budgets and valid empty streams.

Action / next step: Add a shared parse budget for total emitted bytes/nodes, nesting depth and operations, with cancellation propagated through decoding and evaluation. Keep worker isolation at service boundaries.

EN07 · High · Open

Writer symmetry and large-output behavior remain incomplete

Correct scalar output does not make the writer the inverse of every parser feature. Explicit offsets/alignment and bounded structures are not replayed by the current sequential writer; capacity estimates and unchecked size conversion are additional limits.

Evidence: Source inspection: writeStruct walks fields sequentially; estimateCapacity assigns a small estimate to byte-array values; resolveSize still narrows values. These paths are not covered by the new scalar integer fix.

Action / next step: Introduce explicit writer capability rejection, checked sizing and a growing or streaming output sink. Require round trips for every supported feature and negative tests for unsupported profiles before advertising general write support.

A stronger authenticated single-workspace application with reproducible engine integration. It remains a prototype operationally because storage is volatile and runs execute in process.

Next priorities with completion criteria

  1. Engine: close writer correctness gaps. Reject unsupported write features, replace guessed capacity with checked output sizing or a growing sink, and demonstrate round trips for offsets, padding, bounded structures and large payloads.
  2. Engine and SaaS: add a total execution budget. Bound output nodes/bytes, nesting and evaluator operations; support cancellation and execute jobs in isolated workers. Test many small blocks and zero-byte recursive/repeated structures, not only single compressed blocks.
  3. SaaS: make results durable. Use transactional metadata and immutable byte storage; enforce uniqueness across processes; demonstrate restart, concurrency, backup and recovery behavior.
  4. Specification: prove representative GDAL interoperability. Start with GeoTIFF/COG, HDF5/NetCDF, Zarr, GeoPackage, LAS/LAZ and columnar geospatial data. Record exact versions, options, corpora and semantic/decoded comparisons, including explicitly unsupported cases.
  5. Cross-component: independent acceptance. Run clean remote CI, external ontology review, fuzz/differential tests and browser/screen-reader workflows before raising scores toward 10/10.

Standards behind the corrections

Numeric value spaces and lexical mappings follow W3C XML Schema double. The distinction between RDF term identity and value equality follows SPARQL sameTerm. Framing is defined separately by RFC 1950 (zlib) and RFC 1951 (DEFLATE). Inflater completion, dictionary handling and cleanup are documented in the JDK Inflater API.
