Generated counted codec blocks

September 10, 2026. Generated Kotlin supports counted byte fields whose independently encoded elements have one positive fixed encoded size. Each loop iteration now decodes its own block, preserving codec options and the shared request budget.

Correctness correction

The new counterexample exposed an existing writer omission: encoded bytes could be emitted without checking their declared extent. The generated writer now checks the compressed length against a fixed declared size. An oversized block rejects instead of moving the following element or trailer. Inferred lengths retain their measurement behavior. General dynamic encoded-size checks still require deferred validation after layout convergence.

Verification

300 tests pass: 128 lowering, 119 Kotlin backend and 53 generated-code verification tests, with zero failures, errors or skips.

Lowering, Kotlin backend and compiled generated-code verification covers independent JDK level-0 zlib blocks, zero/one/two elements, exact interpreter and generated writer bytes, decoded values, trailer preservation, count mismatch, encoded-size mismatch, a corrupt second block and cumulative decoded limits (six bytes accepted, five rejected). Fixed-count and field-count lowering tests assert that Decode occurs inside the element body. The check also compiles generated sources against the standalone runtime.

Four specification gates pass, including the regenerated processing guide and reproducible review candidate.

Boundaries

Encoded nested structs, repeat-until encoded blocks, dynamic encoded element sizes, conditional element types and data layouts on repeated encoded fields remain rejected. The implementation does not imply support for a whole compressed array as one stream. Independent ontology acceptance and complete release certification remain pending.
