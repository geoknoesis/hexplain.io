The Hexplain Core Ontology provides the essential vocabulary to link physical data structures, described by the Binary Data Description Ontology (BDDO), to their abstract semantic meaning (described by domain vocabularies) and to their multi-dimensional layout (described by the Data Layout Vocabulary). It is the central "glue" of the Hexplain Ontology Family. This specification provides the normative OWL vocabulary, SHACL shapes, and JSON-LD context for Hexplain Core.

This document is an unofficial draft produced for the purpose of defining the Hexplain standard. It has no official standing and is not endorsed by any standards body.

Introduction

The Hexplain framework is designed around layered separation. BDDO describes the physical layout of bytes; domain vocabularies (e.g. the Image Vocabulary) describe conceptual meaning; the Data Layout Vocabulary (DLV) describes multi-dimensional array layout. Hexplain Core provides the small, stable set of properties that connect these layers.

Metamodeling Note (OWL 2 Punning)

The mapping properties relate a physical element (an instance of bddo:Struct or bddo:Field) to a semantic term that is itself an owl:Class or an rdf:Property. Using a class or property as the value of an object property is permitted in OWL 2 DL under punning: the same IRI may denote both a class and an individual. Hexplain Core therefore models all mapping properties uniformly as owl:ObjectProperty and declares their rdfs:range, while — following the family convention — expressing each property's domain as a SHACL constraint rather than an rdfs:domain axiom, so that no subject is silently typed.

Conformance

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [[RFC2119]].

Core Properties

Static Mapping Properties

hexplain:mapsToClass
Links a physical structure to a semantic class. The subject MUST be a bddo:Struct and the object MUST be an owl:Class. It asserts that each parsed instance of the Struct is a physical representation of an instance of that class.
hexplain:mapsToProperty
Links a physical field to a single, unconditional semantic property. The subject MUST be a bddo:Field and the object MUST be an rdf:Property. The field supplies the value of that property.
hexplain:hasDataLayout
Links a bddo:Field that contains multi-dimensional data to a dlv:DataLayout describing how to interpret it (see DLV).
hexplain:isEncodedWith
Specifies the algorithm needed to interpret a block of data — a skos:Concept from whichever codec or compression register the profile binds. A processor MUST decode the block; when the field's data type is a bddo:Struct, it MUST re-parse the decoded bytes against it as a bounded sub-stream.
hexplain:valueExpression / hexplain:valueDatatype
A HEL expression computing the value to emit for the mapped property instead of the raw parsed value (e.g. fixed-point or unit scaling), with an optional result datatype.
hexplain:mapsToObjectProperty
Links a bddo:Field to the owl:ObjectProperty whose object is an IRI rather than a literal — the resource minted for a nested bddo:Struct instance, or the field's enumeration symbol IRI. Use hexplain:mapsToProperty for literal-valued fields and this property for IRI-valued edges, so a described format yields a connected RDF graph rather than isolated literals.
hexplain:unit
The unit of measure of the quantity a bddo:Field carries, as an IRI drawn from a unit vocabulary (e.g. QUDT or UCUM). Annotation only: it records the physical unit of the emitted value and does not rescale it — use hexplain:valueExpression for numeric conversion.
hexplain:language / hexplain:languageFromField
Emit a language-tagged string literal for a bddo:Field: a fixed BCP-47 tag (hexplain:language), or the tag read from a sibling field (hexplain:languageFromField). Mutually exclusive.

Conditional Mapping Properties

Used when the semantic meaning of a field depends on the runtime value of another field.

hexplain:hasConditionalMapping
Links a bddo:Field to an rdf:List of hexplain:MappingRule instances.
hexplain:MappingRule
A single conditional mapping: a condition and the semantic property to apply when it holds.
hexplain:condition
A HEL expression string that evaluates to a boolean.
hexplain:semanticProperty
The rdf:Property applied to the field when the rule's condition is true.
hexplain:hasConditionalClassMapping
Links a bddo:Struct to an rdf:List of hexplain:ClassMappingRule; the class the Struct maps to is the hexplain:semanticClass of the first rule whose condition holds. Models tagged unions / variant records, where a record's type depends on a discriminator field. Mutually exclusive with hexplain:mapsToClass.
hexplain:ClassMappingRule / hexplain:semanticClass
A single conditional class mapping: a hexplain:condition and the owl:Class (hexplain:semanticClass) selected when it holds.

Register Binding Properties

Aspect vocabularies declare properties whose range is skos:Concept but deliberately do not import any register, so a profile states which controlled register supplies a property's values, and the register can be swapped without changing the aspect.

hexplain:usesRegister
States, on a profile, that a property draws its values from a particular controlled register. The object is a hexplain:RegisterBinding.
hexplain:RegisterBinding
One such statement: a pairing of the property being bound with the register that supplies its values.
hexplain:forProperty
The property being bound.
hexplain:register
The skos:ConceptScheme whose members are the permitted values — for example, a profile might bind some ex:status property to an ex:StatusCodes scheme.

# ---------- Encoding pipelines ----------
# One codec is the exception, not the rule. A TIFF strip is horizontally differenced and
# then deflated; an HDF5 dataset runs a filter pipeline (shuffle, then deflate); a Zarr
# array chains delta into Blosc, itself parameterised by an inner codec, a shuffle mode and
# a level; a Parquet page is dictionary- or run-length-encoded before Snappy. With a single
# unparameterised codec, all of these could say only the last step and lost both the earlier
# ones and every setting -- enough to identify the compression but never enough to undo it.
#
# ORDER IS ENCODE ORDER: the steps as the writer applied them, so a reader inverts them in
# REVERSE. Stating this matters, because a pipeline read the wrong way round is still a
# plausible-looking pipeline; TIFF's difference-then-deflate inverts to inflate-then-undifference.
:EncodingStep a owl:Class ; rdfs:label "Encoding Step" ; rdfs:isDefinedBy <https://hexplain.io/ns/core> ;
    rdfs:comment "One stage of an encoding pipeline: a codec, plus the parameters it was applied with." .
:CodecParameter a owl:Class ; rdfs:label "Codec Parameter" ; rdfs:isDefinedBy <https://hexplain.io/ns/core> ;
    rdfs:comment "A named setting of a codec. Deliberately a name/value pair rather than a fixed vocabulary: codec options are open-ended and vendor-specific, and enumerating them would date immediately." .
:hasEncodingStep a owl:ObjectProperty ; rdfs:label "has encoding step" ; rdfs:range rdf:List ; rdfs:isDefinedBy <https://hexplain.io/ns/core> ;
    rdfs:comment "Ordered rdf:List of EncodingStep, in the order the ENCODER applied them; a decoder inverts them in reverse. Mutually exclusive with hexplain:isEncodedWith, which remains the shorthand for a single unparameterised codec." .

# SHACL shapes
hexplain:MapsToClassShape a sh:NodeShape ;
    sh:targetSubjectsOf hexplain:mapsToClass ;
    sh:class bddo:Struct ;
    sh:property [ sh:path hexplain:mapsToClass ; sh:nodeKind sh:IRI ; sh:class owl:Class ] .
hexplain:MapsToPropertyShape a sh:NodeShape ;
    sh:targetSubjectsOf hexplain:mapsToProperty ;
    sh:class bddo:Field ;
    sh:property [ sh:path hexplain:mapsToProperty ; sh:nodeKind sh:IRI ;
        sh:or ( [ sh:class rdf:Property ] [ sh:class owl:DatatypeProperty ]
                [ sh:class owl:ObjectProperty ] [ sh:class owl:AnnotationProperty ] ) ] .
hexplain:HasDataLayoutShape a sh:NodeShape ;
    sh:targetSubjectsOf hexplain:hasDataLayout ;
    sh:class bddo:Field ;
    sh:property [ sh:path hexplain:hasDataLayout ; sh:class dlv:DataLayout ; sh:maxCount 1 ] .
hexplain:IsEncodedWithShape a sh:NodeShape ;
    sh:targetSubjectsOf hexplain:isEncodedWith ;
    sh:property [ sh:path hexplain:isEncodedWith ; sh:nodeKind sh:IRI ; sh:class skos:Concept ; sh:maxCount 1 ] ;
    # A block is encoded one way or the other: a single shorthand codec, or a pipeline.
    sh:not [ sh:and ( [ sh:property [ sh:path hexplain:isEncodedWith ; sh:minCount 1 ] ]
                      [ sh:property [ sh:path hexplain:hasEncodingStep ; sh:minCount 1 ] ] ) ] .

hexplain:EncodingPipelineShape a sh:NodeShape ;
    sh:targetSubjectsOf hexplain:hasEncodingStep ;
    sh:property [ sh:path hexplain:hasEncodingStep ; sh:maxCount 1 ; sh:nodeKind sh:BlankNodeOrIRI ;
        sh:message "hexplain:hasEncodingStep must point to a single rdf:List." ] ;
    sh:property [ sh:path ( hexplain:hasEncodingStep [ sh:zeroOrMorePath rdf:rest ] rdf:first ) ;
        sh:class hexplain:EncodingStep ;
        sh:message "Every member of a hasEncodingStep list must be a hexplain:EncodingStep." ] .

hexplain:EncodingStepShape a sh:NodeShape ;
    sh:targetClass hexplain:EncodingStep ;
    sh:property [ sh:path hexplain:codec ; sh:nodeKind sh:IRI ; sh:class skos:Concept ;
        sh:minCount 1 ; sh:maxCount 1 ;
        sh:message "An encoding step must name exactly one codec." ] ;
    sh:property [ sh:path hexplain:codecParameter ; sh:class hexplain:CodecParameter ] .

# A parameter without both halves says nothing.
hexplain:CodecParameterShape a sh:NodeShape ;
    sh:targetClass hexplain:CodecParameter ;
    sh:property [ sh:path hexplain:parameterName ; sh:datatype xsd:string ; sh:minCount 1 ; sh:maxCount 1 ] ;
    sh:property [ sh:path hexplain:parameterValue ; sh:minCount 1 ; sh:maxCount 1 ] .
hexplain:ValueExpressionShape a sh:NodeShape ;
    sh:targetSubjectsOf hexplain:valueExpression ;
    # A Field computes one value; a MappingRule computes the value for the arm it belongs to.
    # The second was rejected until now, which made conditional mapping able to choose the
    # PROPERTY per condition but never the VALUE -- so a field meaning different things under
    # different discriminators could name the right property and then emit the raw bytes into
    # it. NITF's IGEOLO is the case: 60 characters that are decimal degrees, degrees-minutes-
    # seconds, UTM or MGRS depending on ICORDS, and only the first two are even the same
    # quantity.
    sh:or ( [ sh:class bddo:Field ] [ sh:class hexplain:MappingRule ] ) ;
    sh:property [ sh:path hexplain:valueExpression ; sh:datatype xsd:string ; sh:maxCount 1 ] ;
    sh:property [ sh:path hexplain:valueDatatype ; sh:nodeKind sh:IRI ; sh:maxCount 1 ] .
hexplain:HasConditionalMappingShape a sh:NodeShape ;
    sh:targetSubjectsOf hexplain:hasConditionalMapping ;
    sh:class bddo:Field ;
    sh:property [ sh:path ( hexplain:hasConditionalMapping [ sh:zeroOrMorePath rdf:rest ] rdf:first ) ;
        sh:class hexplain:MappingRule ;
        sh:message "Every member of a hasConditionalMapping list must be a hexplain:MappingRule." ] .

    sh:targetClass hexplain:MappingRule ;
    sh:property [ sh:path hexplain:condition ; sh:nodeKind sh:Literal ; sh:datatype xsd:string ; sh:minCount 1 ; sh:maxCount 1 ] ;
    sh:property [ sh:path hexplain:semanticProperty ; sh:nodeKind sh:IRI ; sh:minCount 1 ; sh:maxCount 1 ;
        sh:or ( [ sh:class rdf:Property ] [ sh:class owl:DatatypeProperty ]

    [ sh:prefix "hexplain" ; sh:namespace "https://hexplain.io/ns/core#"^^xsd:anyURI ] ,

# One shape enforces EVERY hexplain:usesRegister declaration, so adding a binding needs no new
# shape and no generated artifact. Targets exactly those nodes that use a bound property.
hexplain:RegisterBindingShape a sh:NodeShape ;
    sh:target [ a sh:SPARQLTarget ;
        sh:prefixes hexplain:_prefixes ;
        sh:select """SELECT ?this WHERE {
            ?binding hexplain:forProperty ?p .
            ?this ?p ?v .
        }""" ] ;
    sh:sparql [
        sh:message "Value {?value} of {?p} is not skos:inScheme the declared register {?scheme}." ;
        sh:prefixes hexplain:_prefixes ;
        sh:select """SELECT $this ?p ?value ?scheme WHERE {
            ?binding hexplain:forProperty ?p ; hexplain:register ?scheme .
            $this ?p ?value .
            FILTER NOT EXISTS { ?value skos:inScheme ?scheme }
        }""" ] .

Example of Usage

Conditional mapping for the PNG tEXt chunk, where the meaning of TextString depends on the value of the sibling Keyword field.

@prefix bddo:     <https://hexplain.io/ns/bddo#> .
@prefix hexplain: <https://hexplain.io/ns/core#> .
@prefix dfv:      <https://hexplain.io/ns/docfont#> .
@prefix png:      <https://hexplain.io/formats/png#> .
@prefix xsd:      <http://www.w3.org/2001/XMLSchema#> .

png:tEXt_ChunkData a bddo:Struct ;
    bddo:hasField ( png:Keyword png:TextString ) .

png:Keyword a bddo:Field ;
    bddo:dataType bddo:string ;
    bddo:encoding bddo:latin1 ;
    bddo:terminator "00"^^xsd:hexBinary .

png:TextString a bddo:Field ;
    bddo:dataType bddo:string ;
    bddo:encoding bddo:latin1 ;
    # HEL: total chunk length minus the keyword bytes and its 1-byte separator.
    bddo:sizeFromExpression "instance.parent.ChunkLength - (sizeof(instance.parent.Keyword) + 1)" ;
    hexplain:hasConditionalMapping (
        [ a hexplain:MappingRule ; hexplain:condition "instance.parent.Keyword == 'Title'" ;  hexplain:semanticProperty dfv:title ]
        [ a hexplain:MappingRule ; hexplain:condition "instance.parent.Keyword == 'Author'" ; hexplain:semanticProperty dfv:author ]
    ) .
