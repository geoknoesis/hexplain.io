Complete reference: 15 terms and shapes · All vocabularies and reading guide

The Hexplain Geospatial Vocabulary (GV) provides standard terms for geospatial and geointelligence data — raster, vector, and point-cloud formats. Used with BDDO, DLV, and Hexplain Core, it maps low-level fields from GeoTIFF, NetCDF, HDF5, or LAS to high-level concepts. GV is a composition: it defines the dataset kinds and owl:imports the orthogonal aspects that carry the actual concerns — spatial reference (asref:), geometry (ageom:), raster (araster:), point cloud (apc:), provenance (aprov:), and security (asec:). Prefix: gv; namespace: https://hexplain.io/ns/geo#.

This document is an unofficial draft produced for the purpose of defining the Hexplain standard. It has no official standing and is not endorsed by any standards body.

Introduction

Geospatial formats describe how data values map to locations on Earth. BDDO and DLV describe the physical and multi-dimensional layout; GV adds the meaning of fields like "coordinate reference system" or "sensor platform," enabling queries such as "find all Lidar point clouds collected after a date that use WGS 84."

Conformance

The key words "MUST", "SHOULD", "MAY", etc. are to be interpreted as in [[RFC2119]].

Core Concepts (Classes)

gv:GeospatialDataset
A geospatial dataset as a whole.
gv:RasterDataset, gv:VectorDataset, gv:PointCloud
Subclasses for gridded, vector, and point-cloud data — each composing the matching content aspect.
asref:CoordinateReferenceSystem, asref:GeoTransform (aspect)
CRS and affine georeferencing — the spatial-reference aspect.
aprov:AcquisitionInfo, aprov:SensorModel, aprov:Platform (aspect)
Collection-event metadata — the provenance aspect (aligned to PROV/SOSA).

Layout Axes

Geospatial grids use the generic DLV axes dlv:axisX, dlv:axisY and dlv:axisZ; whether an axis runs along longitude, latitude or elevation is stated by the spatial reference, not by the axis individual. gv:axisLatitude, gv:axisLongitude and gv:axisElevation are deprecated duplicates of those axes (dcterms:isReplacedBy), retained so existing descriptions still resolve. GV defines one axis of its own, gv:axisPoint, indexing the points of an unstructured point collection, which has no DLV equivalent.

Example of Usage

A Lidar (LAS) file header and its point record layout, using count-based repetition for the point array.

@prefix bddo:     <https://hexplain.io/ns/bddo#> .
@prefix hexplain: <https://hexplain.io/ns/core#> .
@prefix gv:       <https://hexplain.io/ns/geo#> .
@prefix apc:      <https://hexplain.io/ns/aspect/pointcloud#> .
@prefix las:      <https://hexplain.io/formats/las#> .

las:File a bddo:Struct ;
    hexplain:mapsToClass gv:PointCloud ;
    apc:pointDataLayout las:PointRecordFormat1 ;
    bddo:hasField ( las:NumberOfPointRecords las:Points ) .

las:NumberOfPointRecords a bddo:Field ; bddo:dataType bddo:uint32le ;
    hexplain:mapsToProperty apc:pointCount .

las:Points a bddo:Field ;
    bddo:dataType las:PointRecordFormat1 ;
    bddo:repeatCountFromField las:NumberOfPointRecords .

las:PointRecordFormat1 a bddo:Struct ;
    bddo:endianness bddo:LittleEndian ;
    bddo:hasField ( las:X las:Y las:Z las:Intensity ) .
las:X a bddo:Field ; bddo:dataType bddo:int32 .
las:Y a bddo:Field ; bddo:dataType bddo:int32 .
las:Z a bddo:Field ; bddo:dataType bddo:int32 .
las:Intensity a bddo:Field ; bddo:dataType bddo:uint16 .
