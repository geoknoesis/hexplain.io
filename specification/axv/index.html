The Hexplain Archive Vocabulary (AXV) provides standard terms for the semantic properties of archive and container formats. Used with BDDO and Hexplain Core, it maps low-level fields from formats like ZIP, TAR, 7z, or GZIP to high-level concepts such as file name, uncompressed size, checksum, and modification time, enabling interoperability and semantic querying across archive formats. Prefix: axv; namespace: https://hexplain.io/ns/archive#.

This document is an unofficial draft produced for the purpose of defining the Hexplain standard. It has no official standing and is not endorsed by any standards body. This is the first version. (Earlier drafts of the family listed an "AXV" module whose axv/ path erroneously contained the Audio vocabulary; that content now lives at adv/, and this document is the real Archive Vocabulary.)

Introduction

Archive formats bundle many files, each with metadata (name, sizes, timestamp, integrity check) and an often-compressed payload. BDDO describes the archive's physical structure — including the offset-based layout typical of ZIP central directories, expressible with bddo:atOffset and bddo:offsetBase bddo:streamEnd — while AXV adds the meaning of the metadata fields, enabling queries such as "list all entries larger than 10 MB modified after a given date."

Conformance

The key words "MUST", "SHOULD", "MAY", etc. are to be interpreted as in [[RFC2119]].

Core Concepts (Classes)

axv:Archive
The archive as a whole (ZIP, TAR…).
axv:ArchiveEntry
A single member file or directory within the archive.
axv:CentralDirectory
The index of entries (e.g. the ZIP central directory).

Example of Usage

A ZIP central-directory file header mapped to an ArchiveEntry.

@prefix bddo:     <https://hexplain.io/ns/bddo#> .
@prefix hexplain: <https://hexplain.io/ns/core#> .
@prefix axv:      <https://hexplain.io/ns/archive#> .
@prefix zip:      <https://hexplain.io/formats/zip#> .

zip:CentralDirEntry a bddo:Struct ;
    hexplain:mapsToClass axv:ArchiveEntry ;
    bddo:endianness bddo:LittleEndian ;
    bddo:syncOnMarker "504B0102"^^xsd:hexBinary ;
    bddo:hasField ( zip:CRC32 zip:CompressedSize zip:UncompressedSize zip:FileNameLength zip:FileName ) .

zip:CRC32 a bddo:Field ; bddo:dataType bddo:bytes ; bddo:size 4 ; hexplain:mapsToProperty axv:crcChecksum .
zip:CompressedSize a bddo:Field ; bddo:dataType bddo:uint32 ; hexplain:mapsToProperty axv:compressedSize .
zip:UncompressedSize a bddo:Field ; bddo:dataType bddo:uint32 ; hexplain:mapsToProperty axv:uncompressedSize .
zip:FileNameLength a bddo:Field ; bddo:dataType bddo:uint16 .
zip:FileName a bddo:Field ;
    bddo:dataType bddo:string ; bddo:encoding bddo:utf8 ;
    bddo:sizeFromField zip:FileNameLength ;
    hexplain:mapsToProperty axv:fileName .
