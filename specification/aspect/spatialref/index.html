Coordinate reference systems, affine transforms, control-point sets and rational-polynomial models are distinct resources. The same vocabulary serves raster and vector data without assuming geographic coordinates or one authority’s identifier scheme.

Normative affine contract

X = originX + column × scaleX + row × skewX
Y = originY + column × skewY  + row × scaleY
determinant = scaleX × scaleY − skewX × skewY

A GeoTransform MUST carry all six finite coefficients, including explicit zero skews for north-up imagery. Column/row coordinates refer to pixel corners; the center of the first pixel is (0.5, 0.5). PixelCenter metadata MUST NOT cause a second half-pixel shift after source normalization. Negative scaleY is valid. A singular transform MAY be represented, but inverse evaluation MUST fail when the determinant is zero. Floating implementations MUST document conditioning and tolerance policies; exact nonzero determinants alone do not establish numerical stability.

CRS and control points

CRS WKT is not WKT geometry; no equivalence with GeoSPARQL geometry serialization is asserted. Ground-control-point coordinates MAY use a different CRS from an affine transform. Each GCP MUST include both image and ground coordinate pairs; elevation is optional. Neither GCP interpolation nor precedence among competing geolocation models is inferred. Coordinate epoch describes coordinates in a dynamic frame and is distinct from acquisition time and a datum’s reference epoch.

Rational-polynomial contract

A CubicRationalTransform holds four finite 20-coefficient vectors and five offset/scale pairs. Each scale MUST be positive. A polynomialBasis IRI MUST identify a published contract defining all 20 ordered monomials, normalization, input CRS/units and pixel convention. Different coefficient orders MUST NOT be interchanged. A profile MUST identify the complete contract, not merely label a model “RPC”. A processor MUST report an unsupported basis; this working draft does not mandate a new RPC execution engine.

For a known basis, normalize each input q = (coordinate − offset) / scale, evaluate each numerator and denominator in the declared monomial order, then recover each output as output = offset + scale × numerator / denominator. Zero denominators MUST yield an explicit evaluation error. Structural SHACL validation does not prove that a denominator is nonzero everywhere or that an inverse is unique. Inversion tolerances, height assumptions and convergence failures belong to the processor contract.

Compatibility: the previous shape accepted incomplete GeoTransform resources. Version 1.1 deliberately rejects them. Migrate a complete affine with six coefficients; preserve partial source metadata without asserting a complete GeoTransform. RPC00A/RPC00B conversion and transformation execution remain processor/profile responsibilities.

References: GDAL affine conventions and GDAL RPC metadata contract.
