<https://hexplain.io/ns/aspect/protection> — Hexplain Aspect — Protection (hx-protection)

IRI: https://hexplain.io/ns/aspect/protection

Label
Hexplain Aspect — Protection (hx-protection)
Definition
Aspect describing the cryptographic and error-control protection a format applies to its bytes: encrypted regions, signatures and message authentication codes, and error-correcting codes, each with its algorithm (a register concept) and the fields and byte ranges that parameterise it. Descriptive only: it states what a format declares about its protection, and defines no decryption, verification or correction.
Usage scope
Use in a physical format description to record that a field or struct is encrypted, that a field carries a signature over a byte range, or that a byte range is protected by an error-correcting code. These terms describe protection metadata: a processor is not required to decrypt, verify or correct anything, and lifts protected bytes as the bytes their fields declare. Processing semantics for them are an optional feature a later version may define.

aprot:ByteRange — Byte Range

IRI: https://hexplain.io/ns/aspect/protection#ByteRange

Label
Byte Range
Definition
A contiguous run of bytes bounded by two fields of the description: it begins at the first byte of the field named by aprot:fromField and ends after the last byte of the field named by aprot:toField, both fields included. One field named by both bounds is the range of that field alone.
Usage scope
Assert on the object of aprot:covers, aprot:additionalAuthenticatedData, aprot:dataRange or aprot:parityRange. Both bounds are stated; the fields are members of the description being protected, the first not after the second in reading order.

aprot:EncryptedRegion — Encrypted Region

IRI: https://hexplain.io/ns/aspect/protection#EncryptedRegion

Label
Encrypted Region
Definition
A declaration that the bytes of one field or struct are ciphertext: the region (aprot:region), the cipher (aprot:cipher), and, where the format carries them, the field holding the identifier of the key (aprot:keyIdentifierField), the field holding the initialisation vector or nonce (aprot:nonceField) and the byte range authenticated but not encrypted (aprot:additionalAuthenticatedData).
Usage scope
Assert on a resource of a format description, one per encrypted field or struct. It describes the protection and carries no key: a processor is not required to decrypt the region, and reads it as the bytes the field declares. Decryption is an optional feature a later version may define.

aprot:Signature — Signature

IRI: https://hexplain.io/ns/aspect/protection#Signature

Label
Signature
Definition
A declaration that one field carries a digital signature or message authentication code: the field (aprot:signatureValueField), the algorithm (aprot:signatureAlgorithm), the byte range it is computed over (aprot:covers) and, where the format carries it, the field identifying the signer or the key (aprot:signerIdentifierField).
Usage scope
Assert on a resource of a format description, one per signature or authentication tag. It describes what the format declares: a processor is not required to verify the signature, and a description that states one does not say it is valid. Verification is an optional feature a later version may define. For an unkeyed checksum or digest that a processor does verify, use bddo:Checksum.

# Hexplain Aspect — Protection (hx-protection) 1.0
# Descriptive aspect: which bytes of a format are encrypted, signed or covered by an
# error-correcting code, with what algorithm, and where the fields that parameterise it are.
# It DESCRIBES protection metadata. It defines no processing: a processor is not required to
# decrypt, verify a signature or correct errors, and reads protected bytes as the opaque bytes
# their fields declare. Decryption, verification and correction are an optional feature a later
# version may define; nothing here anticipates its semantics.
# The algorithms are register concepts (register/protection, or a profile's own register), so
# the aspect names none of them.
