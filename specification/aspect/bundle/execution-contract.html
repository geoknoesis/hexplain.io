Bundle facet lifting contract

This companion defines the scope of the published LiftByCarriedAspectRule. It describes the existing query, without adding vocabulary terms or changing its entailment regime.

Inputs and result

The focus is one asset. An explicit hasPart edge selects a part; its role must match a PartSpec of a profile named by the asset's dcterms:conformsTo. A property is copied only when its explicit rdfs:isDefinedBy value matches the PartSpec's carriesAspect. The result replaces the subject with the asset and preserves the predicate and object RDF terms.

CaseResult
Two carriers supply different valuesBoth remain. No priority or conflict resolution is defined.
Two carriers supply the same tripleOne triple under RDF graph set semantics.
Only partOf or primaryPart is assertedNo match without explicit hasPart or separately declared materialization.
Facet is on a nested nodeNo recursive traversal. A copied resource object retains its identity.

Validation boundaries

Lifting is opt-in transformation, not validation. Execute explicitly selected instance shapes on the resulting graph to detect incompatible values. A copied quantity is not aggregated; coordinate systems are not transformed; geometry is not merged. An inference-disabled processor must not silently invent inverse or subproperty edges. Profiles needing them must supply explicit membership or declare a separate preprocessing stage.

Executable code and trust

A processor implementing this fixed rule must select its executable query from a trusted specification artifact. Caller sh:rule or sh:construct triples must not override that selection. Data remains available to the query; trusting the executable query does not establish that metadata is truthful. Record the selected artifact and processing regime for reproducible results.

Resource limits are a separate contract

Engine admission, graph size, write-work and literal-byte limits are implementation controls. Their numeric defaults are not ontology cardinalities. Rejection on resource exhaustion must not be reported as a conforming empty result. Hard query deadlines, total decoding limits and deployed containment require separate evidence.

Competency evidence

Executable cases compare exact output graphs for role selection, conflicts, duplicates, inverse/primary membership and nested properties, with no inference. These cases do not constitute independent ontology review or complete bundle-format coverage.
