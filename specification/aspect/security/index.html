Specification family

Hexplain Aspect — Security Marking (hx-security)

Aspect for security markings, agnostic to the marking system. Provides the spine every system shares — a sensitivity level, verbatim text, an authority, and review/expiry/downgrade dates — plus one open property, asec:marking, through which a system contributes whatever else it defines: compartments, caveats, handling controls, exemption categories, classification reasons, authority types. Each such value is a skos:Concept whose scheme identifies the kind of marking it is, so a new system is supported by publishing registers rather than by extending this aspect. Naming no register is deliberate: it is what lets one profile bind US/NATO markings and another bind something else entirely.

Unofficial working specification. The namespace and version metadata below identify the vocabulary; documentation does not certify an implementation.

asec:LevelChangeShape — Level change completeness

IRI: https://hexplain.io/ns/aspect/security#LevelChangeShape

Label
Level change completeness
Definition
A declared level change must say when it takes effect. asec:levelChangeDate is defined as the date asec:levelChangesTo takes effect, so a change with no date states an obligation nobody can discharge: a reader cannot tell whether the resource is still at the old level or already at the new one. The converse is not required -- a date with no change is a review date, which asec:expiresOn already expresses.

asec:VerbatimLevelShape — Verbatim level text

IRI: https://hexplain.io/ns/aspect/security#VerbatimLevelShape

Label
Verbatim level text
Definition
Advisory, not an error: a resolved asec:sensitivityLevel without the asec:sensitivityLevelText it was resolved from is valid and readable, but it has dropped the bytes the file actually carried. This aspect treats a marking as a legal artefact whose written form matters independently of what it resolves to -- a register revised later must not silently rewrite what a file said -- and once the text is gone that check is no longer possible. Reported at sh:Warning because the marking is correct as far as it goes.

# Hexplain Aspect — Security Marking (hx-security) 2.2
# Governance aspect: security markings. Cross-cutting across any dataset; it does not belong to
# any one domain (it was wrongly trapped in the Geospatial vocabulary).
#
# 2.0 makes the aspect agnostic to the MARKING SYSTEM, not merely to its values. 1.1 already drew
# controlled values from a per-profile register, but its property SET was shaped by US IC ISM:
# declassificationExemption, classificationReason and classificationAuthorityType are categories
# of one national policy. A system that marks documents differently — UK GSC, TLP, an EU scheme,
# a commercial confidentiality scale — had to either abuse those properties or go without.
#
# The spine below is what every marking system has: a level, some text, an authority, dates.
# Everything a particular system ADDS travels through asec:marking, whose values are concepts;
# the concept's skos:inScheme says what KIND of marking it is. Supporting a new system means
# publishing its registers, not editing this file.
