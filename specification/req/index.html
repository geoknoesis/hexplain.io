Specification family

Hexplain Requirements Vocabulary

Identifies requirements stated by an external standards document, so that executable conformance constraints can cite them. Format-agnostic: it describes what documents demand, independent of any binary format description.

Unofficial working specification. The namespace and version metadata below identify the vocabulary; documentation does not certify an implementation.

Conformance

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this section are to be interpreted as described in BCP 14 (RFC 2119 and RFC 8174) when, and only when, they appear in all capitals, as shown here.

  • A requirement is identified by its IRI. It MUST carry exactly one non-empty req:requirementId, req:fromStandard and req:statement, and exactly one req:discrepancyType.
  • Two standards MAY use the same requirement identifier. Within one graph, two distinct requirements MUST NOT carry the same (req:fromStandard, req:requirementId) pair after surrounding whitespace is removed from both values and req:fromStandard is compared ignoring case; req:RequirementIdentityShape enforces it.
  • req:appliesToVersion values are compared by exact string equality with the input's format version, which the caller of a conformance run supplies; an evaluator MUST NOT infer it (Processing Model §Conformance Evaluation).
  • req:discrepancyType classifies a defect and MUST NOT be used to set a finding's severity; severity is the citing constraint's conf:severity.

Definition
Within one graph, a (req:fromStandard, req:requirementId) pair names at most one requirement. # A requirement of the specification itself, as opposed to one a conformance profile declares
# for a format standard. A subclass, and the individuals are typed with it alone: conf:RunShape
# demands an outcome for every resource typed req:Requirement in the graph it validates (a run
# report with its rule set), and the family's own requirements are not part of any rule set.
# Under RDFS entailment each is a req:Requirement; req:RequirementShape still validates each
# through its activation by req:requirementId and the other requirement properties.

:RequirementIdentityShape a sh:NodeShape ;
    sh:targetClass req:Requirement ;
    sh:targetSubjectsOf req:requirementId ;
    rdfs:label "Requirement identity shape"@en ;
    rdfs:comment "Within one graph, a (req:fromStandard, req:requirementId) pair names at most one requirement. The pair is compared after normalising both values (a no-break or other Unicode space counts as a space, zero-width characters and the byte-order mark are removed, and leading and trailing white space is trimmed) and ignoring case in req:fromStandard, so 'MIL-STD-2500C ' and 'mil-std-2500c' are the same standard; the identifier's case is significant. Two distinct requirement resources with the same normalised pair are a violation, reported on each of them. The same identifier under different standards is not."@en ;
    rdfs:isDefinedBy <https://hexplain.io/ns/req> ;
    sh:sparql [
        sh:message "Another req:Requirement ({?other}) has the same req:fromStandard and req:requirementId (after trimming, and ignoring the standard's case); the pair must be unique." ;
        sh:prefixes req:_prefixes ;
        sh:select """SELECT $this ?other WHERE {
            $this req:fromStandard ?std ; req:requirementId ?id .
            ?other req:fromStandard ?std2 ; req:requirementId ?id2 .
            FILTER(!sameTerm(?other, $this))
            FILTER(LCASE(REPLACE(REPLACE(REPLACE(STR(?std), "[\u00A0\u1680\u2000-\u200A\u202F\u205F\u3000]", " "), "[\u200B-\u200D\u2060\uFEFF]", ""), "^[ \\t\\r\\n]+|[ \\t\\r\\n]+$", "")) = LCASE(REPLACE(REPLACE(REPLACE(STR(?std2), "[\u00A0\u1680\u2000-\u200A\u202F\u205F\u3000]", " "), "[\u200B-\u200D\u2060\uFEFF]", ""), "^[ \\t\\r\\n]+|[ \\t\\r\\n]+$", "")))
            FILTER(REPLACE(REPLACE(REPLACE(STR(?id), "[\u00A0\u1680\u2000-\u200A\u202F\u205F\u3000]", " "), "[\u200B-\u200D\u2060\uFEFF]", ""), "^[ \\t\\r\\n]+|[ \\t\\r\\n]+$", "") = REPLACE(REPLACE(REPLACE(STR(?id2), "[\u00A0\u1680\u2000-\u200A\u202F\u205F\u3000]", " "), "[\u200B-\u200D\u2060\uFEFF]", ""), "^[ \\t\\r\\n]+|[ \\t\\r\\n]+$", ""))
        }""" ;
    ] .

        sh:message "req:fromStandard takes an xsd:string literal (rdfs:range xsd:string)." ] ;
    sh:property [ sh:path req:requirementId ; sh:datatype xsd:string ;
        sh:message "req:requirementId takes an xsd:string literal (rdfs:range xsd:string)." ] .
