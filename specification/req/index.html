Specification family

Hexplain Requirements Vocabulary

Identifies requirements stated by an external standards document, so that executable conformance constraints can cite them. Format-agnostic: it describes what documents demand, independent of any binary format description.

Unofficial working specification. The namespace and version metadata below identify the vocabulary; documentation does not certify an implementation.

Conformance

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this section are to be interpreted as described in RFC 2119.

  • A requirement is identified by its IRI. It MUST carry exactly one non-empty req:requirementId, req:fromStandard and req:statement, and exactly one req:discrepancyType.
  • Two standards MAY use the same requirement identifier. Within one graph, two distinct requirements MUST NOT carry the same (req:fromStandard, req:requirementId) pair after surrounding whitespace is removed from both values and req:fromStandard is compared ignoring case; req:RequirementIdentityShape enforces it.
  • req:appliesToVersion values are compared by exact string equality with the input's format version, which the caller of a conformance run supplies; an evaluator MUST NOT infer it (Processing Model §Conformance Evaluation).
  • req:discrepancyType classifies a defect and MUST NOT be used to set a finding's severity; severity is the citing constraint's conf:severity.

req:RequirementIdentityShape — Requirement identity shape

IRI: https://hexplain.io/ns/req#RequirementIdentityShape

Label
Requirement identity shape
Definition
Within one graph, a (req:fromStandard, req:requirementId) pair names at most one requirement. The pair is compared after normalising both values (a no-break or other Unicode space counts as a space, zero-width characters and the byte-order mark are removed, and leading and trailing white space is trimmed) and ignoring case in req:fromStandard, so 'MIL-STD-2500C ' and 'mil-std-2500c' are the same standard; the identifier's case is significant. Two distinct requirement resources with the same normalised pair are a violation, reported on each of them. The same identifier under different standards is not.
Usage scope
Validation activation: instances of req:Requirement; subjects using req:requirementId Constraints apply only within that activation or through shape references; they are not global OWL domain axioms.

req:appliesToVersion — applies to version

IRI: https://hexplain.io/ns/req#appliesToVersion

Label
applies to version
Definition
A format version the requirement governs (e.g. 'NITF 2.1'). Absence means the requirement applies to every version of the format. Multiple values are a union: the requirement applies to an input whose format version equals any one of them. The input's version is supplied to the conformance run by its caller and compared with each value by exact string equality; when the caller supplies none, every requirement is evaluated and the run reports that version scoping was not applied.
Usage scope
Use zero or more times on a req:Requirement; each value is a non-empty string spelt exactly as callers will supply the version.
