Security profile mutation contract

This acceptance contract exercises the opt-in example profile. It does not establish an access-control policy, clearance ordering, implicit inheritance or authorization.

Each mutation removes exactly one constraint triple. The baseline failure must identify the expected result path, and the valid control must still conform after mutation. Removing the target class separately makes all seven retained negative cases conform vacuously. That result illustrates why a conforming report is insufficient unless expected target activation is established.

The tests run without inference. They use byte-identical profile and corpus resources in the specification and engine. Mutants exist only in memory and never replace published shapes.
