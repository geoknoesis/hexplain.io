Shared specification patterns

This editorial guide summarizes existing contracts. It adds no vocabulary, fallback policy or implementation capability. Canonical RDF and the linked processing contracts remain authoritative.

Value sources

Literal values, field references and expressions are alternative ways to obtain values. Retain their distinct public properties and evaluation contexts. A field reference can identify a writer-inferable dependency; an arbitrary expression does not establish an inverse.

Do not replace sizeFromField with an equivalent-looking expression. Fixed sizes remain constraints. Preserve units, scope, exact integer conversion, absence and inheritance for each consuming property.

Ordered selection

Ordered conditional rules select the first applicable rule. This common description does not supply a universal fallback or evaluation phase.

Type selection retains dispatchDefault/dataType fallback and its missing-type error. Mapping, cell type, dimension order and byte order retain their own activation, defaults and errors. Keyed dispatch collects uniquely keyed arms across the graph; it is not an ordered predicate list.

Existing contract

Encoding shorthand

isEncodedWith denotes a single unparameterized codec. hasEncodingStep is an ordered pipeline in encoder order; decoding traverses that order in reverse.

Preserve mutual exclusion, parameters, codec framing, decoded address space, region bounds and capability rejection. A pipeline description does not imply that every parser or writer supports it.

Existing contract

Constraint reuse

Private authoring fragments expand into the existing shapes before publication. Targets stay on their original shapes; reusable value constraints do not acquire domain-wide activation.

Preserve the exact datatype alternatives, RDF list order, count and numeric bounds, messages, severity and result structure. Similar-looking raster and sampling constraints are not interchangeable.
