The Hexplain Image Vocabulary (IDV) provides a standard set of terms for the semantic properties of raster images. Used with BDDO and Hexplain Core, it lets format authors map low-level physical fields to high-level concepts (image width in pixels, colour type, compression), enabling interoperability and semantic querying across image formats. It owl:imports the aspect layer, so raster dimensions (araster:width/height), per-component precision (asamp:bitDepth), and colour space (acolor:colorSpace) are shared with the other media vocabularies rather than image-specific. Prefix: img; namespace: https://hexplain.io/ns/image#.

This document is an unofficial draft produced for the purpose of defining the Hexplain standard. It has no official standing and is not endorsed by any standards body.

Introduction

BDDO describes the physical structure of a file; IDV describes what raster image data means. Common URIs for "pixel width," "colour space," and "compression" let a processor compare images across formats (PNG, JPEG, BMP) and answer questions like "find all images wider than 1024 pixels" without knowing each format's byte layout.

Conformance

The key words "MUST", "MUST NOT", "SHOULD", "MAY", etc. are to be interpreted as in [[RFC2119]].

Core Concepts (Classes)

img:Image
The image as a whole.
img:ImageHeader
The metadata block holding primary characteristics (dimensions, colour).
img:ColorProfile
Colour space, gamma, etc.
img:PixelData
The compressed or uncompressed pixel data.

Semantic Properties

A bddo:Field uses hexplain:mapsToProperty to link to one of these. Ranges are enforced by the SHACL shapes below.

PropertyDescriptionRange
araster:width, araster:height (aspect)Dimensions in pixels (raster grid extent).xsd:positiveInteger
asamp:bitDepth (aspect)Bits per colour/sample component.xsd:positiveInteger
acolor:colorSpace (aspect)Colour space, from the Colour Space Register.skos:Concept
img:colorType (PNG)Colour-type code (Grayscale, RGB, Indexed…).xsd:integer
img:compressionMethod (PNG)Compression-method code.xsd:integer
img:filterMethod (PNG)Filter/prediction-method code.xsd:integer
img:interlaceMethod (PNG)Interlace/progressive-method code.xsd:integer

Layout Axes

IDV reuses the Data Layout Vocabulary axes rather than defining duplicates: use dlv:axisX (width), dlv:axisY (height), and dlv:axisBand (channel/component) inside a dlv:Dimension.

Example of Usage

@prefix bddo:     <https://hexplain.io/ns/bddo#> .
@prefix hexplain: <https://hexplain.io/ns/core#> .
@prefix rdfs:     <http://www.w3.org/2000/01/rdf-schema#> .
@prefix img:      <https://hexplain.io/ns/image#> .
@prefix araster:  <https://hexplain.io/ns/aspect/raster#> .
@prefix asamp:    <https://hexplain.io/ns/aspect/sampling#> .
@prefix png:      <https://hexplain.io/formats/png#> .

png:IHDR_ChunkData a bddo:Struct ;
    hexplain:mapsToClass img:ImageHeader ;
    bddo:endianness bddo:BigEndian ;
    bddo:hasField ( png:Width png:Height png:BitDepth png:ColorType ) .

png:Width  a bddo:Field ; bddo:dataType bddo:uint32 ; hexplain:mapsToProperty araster:width .
png:Height a bddo:Field ; bddo:dataType bddo:uint32 ; hexplain:mapsToProperty araster:height .
png:BitDepth a bddo:Field ; bddo:dataType bddo:uint8 ; hexplain:mapsToProperty asamp:bitDepth .
png:ColorType a bddo:Field ; bddo:dataType bddo:uint8 ; hexplain:mapsToProperty img:colorType ;
    bddo:enumeration [ a bddo:Enumeration ; bddo:hasEnumValue
        [ a bddo:EnumValue ; bddo:enumRawValue 0 ; rdfs:label "Grayscale" ] ,
        [ a bddo:EnumValue ; bddo:enumRawValue 2 ; rdfs:label "RGB" ] ,
        [ a bddo:EnumValue ; bddo:enumRawValue 3 ; rdfs:label "Indexed" ] ] .
