Specification family

Hexplain SPARQL function library (hxf)

Custom SPARQL functions that reach the bytes, parsed values, array cells and aspect coordinates of a file described by a Hexplain profile. Functions bind to the description vocabularies, never to a format.

Unofficial working specification. The namespace and version metadata below identify the vocabulary; documentation does not certify an implementation.

Overview

The graph a Hexplain profile lifts from a file describes the file; it does not contain it. The hxf library is a set of custom SPARQL functions, one IRI per function in the namespace https://hexplain.io/ns/fn#, that reach past the description graph into the bytes, parsed values, array cells and aspect coordinates of the asset the graph describes. Every function is written once against the description vocabularies (BDDO, DLV, core, the aspects) and works for any profile that uses them; none knows what TIFF, NITF, PNG, Zarr, WAV or a shapefile is.

Layer 0 — bytes. hxf:bytes and hxf:digest read a lifted node's recorded hexplain:byteOffset and hexplain:byteLength (emitted by the lifter's ExtractOptions.includeByteRange) and then need only the asset's bytes, not its profile or a parse. hxf:decodedBytes instead reads the node's encoding chain (hexplain:isEncodedWith, hexplain:hasEncodingStep) and still needs the parse, because the codec chain lives in the profile. All three work for any node of any format because they touch only core properties.

Layer 1 — parsed values. hxf:value returns a node's parsed scalar even when the profile did not map it to a triple; hxf:hel evaluates a HEL expression with the node as instance; hxf:decode decodes a scalar from raw bytes by a BDDO primitive datatype.

Layer 2 — arrays (DLV). hxf:rank, hxf:extent, hxf:cell, hxf:stat and the hxf:window property function address the cells of any node whose field carries a dlv:DataLayout: raster grids, netCDF and Zarr variables, PCM audio, point records, lookup tables.

Layer 3 — aspect coordinates. A small composition of layers 0–2 with an aspect's vocabulary: hxf:sampleAt, hxf:calibrate, hxf:isNoData and hxf:physicalAt for araster:; hxf:worldX, hxf:worldY, hxf:column, hxf:row and hxf:sampleAtWorld for asref: affine georeferencing; hxf:wkt for geometry; hxf:sampleAtTime for signals.

Diagnostics. hxf:explain and hxf:layout exist so that an unbound result is never a dead end.

Argument conventions. A node argument is always a lifted instance IRI, never a file path. Array indices are zero-based and given in the layout's declared dimension order. The raster layer instead uses logical x (column) and y (row), and identifies a band either by its araster:RasterBand IRI or by its one-based araster:bandIndex, matching the aspect and GDAL; hxf:sampleAtTime's channel argument is likewise one-based. The two index conventions are documented side by side rather than harmonised, because each matches the vocabulary it serves.

Result typing. Results are typed by the cell type: integer cells return xsd:integer, float cells xsd:double, string cells xsd:string, byte cells xsd:hexBinary. Geometry returns geo:wktLiteral so GeoSPARQL's geof: functions apply directly.

Failure contract. Failure is unbound, never a query error. An out-of-range index, an unresolvable asset, a layout the engine cannot execute, or an oversize request all leave the result variable unbound (or make the enclosing FILTER false) rather than raising. The reason is exposed through hxf:explain(node), which describes how the runtime resolved the node and why its last call failed, and is never itself unbound.

Worked queries

Pixel at a coordinate, calibrated, for any raster format:

PREFIX hxf: <https://hexplain.io/ns/fn#>
PREFIX araster: <https://hexplain.io/ns/aspect/raster#>
SELECT ?grid ?value WHERE {
  ?grid a araster:RasterGrid ; araster:hasBand ?band .
  ?band araster:bandIndex 1 .
  BIND(hxf:physicalAt(?grid, 412, 97, ?band) AS ?value)
}

Value under a world point across a folder of mixed NITF, GeoTIFF and raw grids:

PREFIX hxf: <https://hexplain.io/ns/fn#>
PREFIX geo: <http://www.opengis.net/ont/geosparql#>
SELECT ?dataset ?v WHERE {
  ?dataset a geo:RasterDataset .
  BIND(hxf:sampleAtWorld(?dataset, -122.41, 37.77, 1) AS ?v)
  FILTER(bound(?v))
}

Mean of a window on a netCDF variable, by axis rather than by position — the array is found by araster:hasArray, which links a grid to its sample array by edge rather than by asserting araster:SampleArray on the array itself:

PREFIX hxf: <https://hexplain.io/ns/fn#>
PREFIX araster: <https://hexplain.io/ns/aspect/raster#>
PREFIX dlv: <https://hexplain.io/ns/dlv#>
SELECT (hxf:stat(?a, "mean", 0, 1, 100, 200, 100, 200) AS ?m) WHERE {
  ?grid araster:hasArray ?a .
  FILTER(hxf:extent(?a, dlv:axisTime) > 0)
}

Read an unmapped header field, by name rather than by whatever the profile chose to map:

PREFIX hxf: <https://hexplain.io/ns/fn#>
SELECT ?tag ?count WHERE {
  ?entry a tiff:IfdEntry .
  BIND(hxf:hel(?entry, "Tag") AS ?tag)
  BIND(hxf:value(?entry) AS ?count)
}
