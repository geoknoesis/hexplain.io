Specification family

Hexplain Conformance Vocabulary

Binds executable HEL assertions to the standards requirements they check. Format-agnostic. Severity is deliberately absent: it derives from the cited requirement's req:discrepancyType, so a rule reused across profiles is classified consistently.

Unofficial working specification. The namespace and version metadata below identify the vocabulary; documentation does not certify an implementation.

Complete term and shape reference

7 named resources are documented below. Definitions and usage notes come from the canonical RDF; range and validation facts are rendered from its axioms and shapes. RDFS/OWL inference, SHACL validation, and editorial usage guidance are shown separately. Blank-node property shapes and logical alternatives are expanded under their owning named shapes.

Constraint language follows W3C SHACL; publication and persistent term identifiers follow the W3C vocabulary publication guidance. Concept definitions and scope notes use SKOS documentation properties.

conf:ConstraintShape — Constraint shape

IRI: https://hexplain.io/ns/conf#ConstraintShape

Label
Constraint shape
Definition
A reusable validation contract for conf:assertion, conf:message, conf:satisfies, conf:scope. A Constraint must cite at least one req:Requirement; an unattributed rule cannot be reported. A Constraint needs exactly one conf:message finding template. A Constraint needs exactly one conf:scope IRI naming the struct or field it applies to. A Constraint needs exactly one non-empty conf:assertion HEL expression.
Usage scope
Validation activation: instances of conf:Constraint Constraints apply only within that activation or through shape references; they are not global OWL domain axioms.
Declared RDF type
sh:NodeShape
Domain / range
Not applicable to this node shape. Domain and range describe predicates; the types, relationships and constraints below describe this resource.
Defined by
<https://hexplain.io/ns/conf>
Activation
instances of conf:Constraint
Severity
SHACL default: sh:Violation. This applies to results of this shape; nested property shapes have their own severity (default sh:Violation), rather than inheriting it. Rules generate triples instead of validation results.
