Codec vector suites

Every concept of the media-encoding register that carries a hexplain:codecContract (a contracted concept) has a normative vector suite under specification/codecs/<LocalName>/vectors/: a manifest.json, and any input files it names beside it. The Processing Model makes the suite normative (req-pm-codec-contracts-1: a processor decodes a codec exactly as its contract and its vectors define it, and a vector's expected output or error category is normative). The manifest format is defined here and by the machine-readable schema vector-manifest.schema.json (JSON Schema 2020-12); tools/codecs/vectors.py is the reference loader and comparator, and tools/test_codec_contracts.py and tools/test_codec_vector_completeness.py, two gates, hold every suite to it.

The manifest

A manifest is a JSON object with five members and no others: codec, suiteVersion, sources and vectors are required, and unreached is optional. The published schema states the same, and tools/test_codec_vector_completeness.py validates every manifest against it:

MemberValue
codecThe concept's IRI (https://hexplain.io/ns/register/media-encoding#Zlib).
suiteVersionAn integer equal to the contract's hexplain:vectorSuiteVersion. A change to any vector's expectation raises both; adding a vector does not.
sourcesThe provenance of the inputs and expectations: objects with an id, a description naming the library, tool or document that produced them, with its version, and how any corruption was made, a licence, and optionally a url. A suite records at least one source, and every vector names one.
vectorsThe vectors, each an object with a unique id (lower-case letters, digits, . and -), its source, one or more steps, optionally session: true when the steps share one codec session (a codec whose contract keeps a session: JPEG tables, a fax coding's reference line), and optionally an expectAll.
unreached (optional)An object whose keys are categories the contract declares (Validation, Checksum, Unsupported, ResourceLimit) and that no input of any known implementation raises, each with the reason as a non-empty string (). A suite with nothing to record omits the member.

A step runs the codec once:

MemberValue
directiondecode, encode or describe (report the geometry of an encoded image without decoding its samples).
paramsThe codec parameters by the contract's keys, as JSON values of the contract's types: integers and floats as numbers, booleans, strings, bytes as {"hex": …} or {"base64": …}, IRIs as {"iri": …}, and a list-valued parameter as an array of those. A step's parameters obey the contract (declared names, required ones present, values of the right type within the declared values or range) unless the step expects a Description error, which is what a step that breaks the contract asserts.
inputThe bytes the step reads: {"hex": …}, {"base64": …}, {"file": name} (a file beside the manifest) or, for a codec that reads samples, {"samples": {width, height, bands, sampleType, hex | base64}}, the samples little-endian and pixel-interleaved; or {"previous": true}, the output of the step before it, which must have succeeded. Each other step has its own input. A round trip is an encode step followed by a decode step: for a transform whose encoding is fixed by its definition (Delta, the floating-point predictor) the decode step carries the encode step's expected output as its own input and expects the encode step's input back; for a compressor, whose encoded bytes are the implementation's own and never normative, the encode step expects {"ok": true} and the decode step reads {"previous": true}.
maxOutputBytesThe decoded-byte limit the step runs under (default 67,108,864). A vector that expects ResourceLimit sets it below the output's size: the Processing Model requires the limit to be met as the output is produced (decompression bombs).
expectWhat the step yields: the exact output as {"hex": …} or {"base64": …}; its digest and optionally size as {"sha256": …, "size": n}; {"ok": true} when only expectAll checks it; for samples, {"samples": {width, height, bands, sampleType, sha256, order}}, the digest covering the samples pixel-interleaved (order pixel, the default) or rewritten band-sequentially (band); any success form with a validitySha256 over the per-band validity masks of samples that carry them; or {"error": category}.

Error categories. error is one of Validation, Checksum, Unsupported, ResourceLimit and Description, the conformance-suite notation of the Processing Model's categories. The first four are the categories a contract declares with hexplain:raisesCategory, and a suite carries at least one vector for each category its contract declares. Description is the category of a step whose parameters the contract rejects (req-pm-codec-contracts-2): every codec raises it, so a contract does not declare it, and the register's contract shape (hexplain:CodecContractShape) admits it among the declarable categories so that a contract may state it explicitly.

expectAll. For a vector whose steps are the strips or tiles of one image, expectAll gives a sha256 (and optionally size) over the concatenation of every step's output, after an optional unpack (each row of width samples of bitsPerSample bits, most significant bit first, widened to one byte per sample, the row's padding bits dropped) and an optional deinterleave (pixel-interleaved samples of bands bands of sampleBytes bytes each rewritten band-sequentially). A step that fails ends the vector.

What every suite carries

A suite is the executable statement of its contract, so it has to reach every part of the contract. tools/test_codec_vector_completeness.py fails a suite that lacks any of these:

  • at least one decoding vector that succeeds;
  • for every category the contract declares with hexplain:raisesCategory, at least one step that expects it (a ResourceLimit vector lowers maxOutputBytes; a Validation vector truncates or corrupts a valid input; a Checksum vector flips a check; an Unsupported vector uses a coding feature the contract names as refused);
  • for every parameter the contract declares, at least one step that succeeds and passes a value the contract admits (inside its bounds and allowed values), in the direction the parameter applies: a parameter that only steers the encoder — the compression level of Deflate, Zlib and XZ — on an encode step, whose output the next decode step reads back, and any other parameter on a step of either direction the contract covers. A step that expects the parameter's refusal (a level of 10) shows that a bad value is refused, not that a good one is honoured, and does not count;
  • for a codec whose contract encodes (hexplain:encodes true on the contract; a suite whose contract does not state it holds no encode step), at least one round trip: an encode step followed by a decode step whose input is the encode step's expected output and whose expected output is the encode step's input, which is what the Processing Model's symmetry requirement says of a codec.

A category the contract declares that no input of any known implementation raises is a defect of the contract, not something a suite can paper over: the manifest records it under unreached with the reason, the gate reports it as a warning rather than a failure, and the register is to withdraw the category. No suite records one today: the XZ contract declared Unsupported, which no XZ stream raises, and the register has withdrawn it.

Expected outputs come from an implementation independent of the reference engine wherever one exists — the zlib, liblz4, zstd, liblzma, numcodecs and libtiff (through GDAL) libraries, or the Processing Model's own worked examples — and each suite's sources say which; where no independent implementation exists, the reference engine's output is recorded and the source says so, so a second implementation that disagrees knows what it is disagreeing with.

Running a suite

tools/codecs/run_vectors.py runs every suite, or the suites named with --codec, against one implementation through a command template that runs one vector and prints one JSON result:

python tools/codecs/run_vectors.py --command "hexplain-codec vector --manifest {manifest} --id {id}" --codec Zlib
python tools/codecs/run_vectors.py --command "python tools/codecs/_python_reference.py vector --manifest {manifest} --id {id}" --codec Store --codec Deflate --codec Zlib --codec Gzip

The result is {"steps": [...], "all": {...}}: per step {"ok": true, "size": n, "sha256": …} with geometry, sha256Band and validitySha256 for samples, or {"ok": false, "category": …, "message": …}; all covers the concatenated outputs for a vector with expectAll. tools/codecs/_python_reference.py, a plain-Python Store, Deflate, Zlib and Gzip that shares no code with the reference engine, is run through it by tools/test_codec_contracts.py, which proves the runner and the four minimum-set suites end to end.

The suites

One directory per contracted concept, listed by the register: BitReverse, BitRound, Blosc, BloscLZ, CCITTGroup3, CCITTGroup4, CCITTModifiedHuffman, CIELabToRGB, CMYKToRGB, Deflate, Delta, FixedScaleOffset, FloatingPointPredictor, Gzip, JPEG, JPEGXL, LERC, LZ4, LZ4Block, LZW, MicrosoftRLE, NeXT, PackBits, Quantize, SGILogRLE, Shuffle, Store, ThunderScan, TypedDelta, WebP, XZ, YCbCrToRGB, Zlib and Zstd. The gate tools/test_codec_contracts.py fails when a contracted concept has no suite, or a suite has no contracted concept.
