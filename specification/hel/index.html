The Hexplain Expression Language (HEL) is a small, declarative language for the conditions and calculations inside Hexplain format descriptions. It powers dynamic sizing, conditional presence, repetition counts, offsets, and conditional data-type and semantic dispatch. HEL operates on a hierarchical logical data model derived from the binary data being parsed, using name resolution inspired by JSON-LD.

This document is an unofficial draft produced for the purpose of defining the Hexplain standard. It has no official standing and is not endorsed by any standards body.

Introduction

A key requirement of the Hexplain framework is handling dynamic structures where the presence, size, count, offset, or type of a field depends on previously parsed data. HEL provides a concise, unambiguous syntax for these expressions. Design goals: simplicity, clarity, and grounding in stable standards (JSON-LD name resolution, XPath operator semantics).

HEL literals appear as the value of the properties bddo:isPresentIf, bddo:repeatUntil, bddo:sizeFromExpression, bddo:repeatCountFromExpression, bddo:atOffsetFromExpression, bddo:coversExpression, bddo:condition, and hexplain:condition.

Conformance

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [[RFC2119]].

The Logical Data Model

A HEL expression is evaluated against a temporary, in-memory parsing context — a hierarchical tree that the processor builds as it parses. Each parsed Struct instance is a node whose named children are its fields; each scalar field yields a value node; a repeated field yields an ordered array node.

Reserved Roots

An expression is attached to a specific description element (a Field, a DataTypeRule, a MappingRule, or a Checksum). Evaluation resolves the following reserved roots relative to that element:

RootDenotes
instanceThe current node — the parsed node the expression is attached to (its Field, or the Struct/Field a rule governs).
parentShorthand for instance.parent: the containing Struct node. Sibling fields are reached via parent.SiblingName (equivalently instance.parent.SiblingName).
rootThe top-level parsed instance (the outermost Struct of the description).
selfWithin a bddo:repeatUntil expression, the array element most recently parsed (the one under test). Undefined elsewhere.
streamStream metadata: stream.length, stream.position, stream.remaining (all byte counts, integers).

Context-Based Key Resolution

Identifiers after a dot are simple keys (e.g. ChunkType). They resolve to full IRIs via the @prefix context of the Hexplain description, exactly as in [[JSON-LD]]. A key MUST correspond to a field defined in the referenced Struct, or to the keyword parent.

An array node (a repeated field) MAY be subscripted with [ Expression ]. The index expression MUST evaluate to a non-negative Integer strictly less than the array's length (elements are 0-based); otherwise a range error is raised. Subscripts and key steps compose freely (e.g. root.Directory[i].Entries[0].Tag).

Syntax and Grammar

Formal Grammar (ABNF)

The following grammar [[RFC5234]] defines HEL. Operators are listed lowest-precedence first.

Expression   = OrExpr
OrExpr       = AndExpr *( WS "or" WS AndExpr )
AndExpr      = NotExpr *( WS "and" WS NotExpr )
NotExpr      = [ "not" WS ] Comparison
Comparison   = BitOrExpr [ WS CompOp WS BitOrExpr ]
BitOrExpr    = BitXorExpr *( WS "|" WS BitXorExpr )
BitXorExpr   = BitAndExpr *( WS "^" WS BitAndExpr )
BitAndExpr   = ShiftExpr  *( WS "&" WS ShiftExpr )
ShiftExpr    = AddExpr    *( WS ( "<<" / ">>" ) WS AddExpr )
AddExpr      = MulExpr    *( WS ( "+" / "-" ) WS MulExpr )
MulExpr      = Unary      *( WS ( "*" / "/" / "%" ) WS Unary )
Unary        = [ "-" / "~" ] Primary
Primary      = FunctionCall / Accessor / Literal / ( "(" WS Expression WS ")" )

FunctionCall = FunctionName "(" WS [ Expression *( WS "," WS Expression ) ] WS ")"
FunctionName = "sizeof" / "len" / "count" / "eof" / "trim" / "substringBefore" / "substringAfter" / "number"

Accessor     = Root *( Step )
Step         = "." ( "parent" / IDENTIFIER ) / "[" WS Expression WS "]"
Root         = "instance" / "parent" / "root" / "self" / "stream"

CompOp       = "==" / "!=" / "<=" / ">=" / "<" / ">"
Literal      = StringLiteral / HexLiteral / IntegerLiteral / BooleanLiteral
StringLiteral= %x27 *( SChar / Escape ) %x27       ; single-quoted
Escape       = "\" ( %x27 / "\" )                  ; \' or \\
SChar        = %x20-26 / %x28-5B / %x5D-7E          ; any char except ' and \
HexLiteral   = "0x" 1*HEXDIG
IntegerLiteral = 1*DIGIT
BooleanLiteral = "true" / "false"
IDENTIFIER   = ALPHA *( ALPHA / DIGIT / "_" )
WS           = *( %x20 / %x09 )

Comparison and arithmetic operator semantics follow their counterparts in [[xpath-functions-31]]. Bitwise operators operate on integer values using two's-complement semantics at the operand's bit width.

Evaluation Semantics

Operator Precedence

From highest to lowest: grouping () and function calls; unary -/~; * / %; + -; shifts << >>; bitwise &; bitwise ^; bitwise |; comparisons; not; and; or. Within one level, evaluation is left to right.

Value Types

Every HEL value is one of: Integer, Float, Boolean, String, Bytes, or Null (an absent/optional field). A field's parsed value takes the HEL type implied by its bddo:DataType's bddo:baseType: bddo:baseInteger → Integer, bddo:baseFloat → Float, bddo:baseString → String, bddo:baseBytes → Bytes. This is determined by baseType alone, so the ASCII-coded numeric types bddo:asciiInteger and bddo:asciiDecimal yield Integer and Float respectively and may be used wherever a number is required.

Type Coercion & Comparison Rules

These rules are normative and resolve the comparisons used throughout Hexplain (e.g. comparing a 4-byte ChunkType to 'IHDR'):

  • Arithmetic / bitwise operands MUST be numeric. Mixing Integer and Float promotes to Float. Bitwise operators require Integer operands. A non-numeric operand is an error.
  • Bytes vs. String. When one operand is Bytes and the other is a String literal, the Bytes value is decoded to a String using the field's bddo:encoding (default bddo:utf8) before comparison. Equality holds iff the decoded strings are code-point-identical.
  • String vs. String compares by Unicode code point; < > <= >= use code-point order.
  • Integer vs. Float compares by numeric value.
  • Null. An access to an absent optional field yields Null. Null == Null is true; any other comparison with Null is false; arithmetic with Null is an error.
  • Comparing values of otherwise incompatible types (e.g. Boolean vs. Integer) is an error.

Conformance

A conforming HEL implementation MUST:

  1. Parse all valid expressions per the ABNF grammar.
  2. Implement the parsing context and all reserved roots (instance, parent, root, self, stream).
  3. Implement all operators and functions with the specified precedence, and the value-type and coercion rules.
  4. Yield a Boolean in a boolean context (e.g. bddo:isPresentIf, bddo:repeatUntil, conditions), an Integer in a numeric context (e.g. bddo:sizeFromExpression, bddo:repeatCountFromExpression, bddo:atOffsetFromExpression), and a String in a string context (e.g. a hexplain:valueExpression whose hexplain:valueDatatype is xsd:string).
  5. Report a runtime error (rather than silently continue) on type errors, division/modulo by zero, and references to undefined names.

Examples

Sibling reference (conditional mapping)
hexplain:condition "instance.parent.Keyword == 'Title'"
Dynamic sizing with sizeof
bddo:sizeFromExpression "instance.parent.ChunkLength - (sizeof(instance.parent.Keyword) + 1)"
Bit-mask (IPv4 header length in bytes)
bddo:sizeFromExpression "(instance.parent.VersionIHL & 0x0F) * 4"
Repeat until end of stream
bddo:repeatUntil "eof()"
Count-driven presence
bddo:isPresentIf "instance.parent.Flags & 0x01 == 0x01"
Trimming a delimited header value
hexplain:valueExpression "trim(instance.parent.description)"
Splitting a compound header value
hexplain:valueExpression "number(substringBefore(instance.parent.mapInfo, ','))"
