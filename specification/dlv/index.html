The Hexplain Data Layout Vocabulary (DLV) describes the organization of multi-dimensional data within a flat binary stream. It is a companion to the Binary Data Description Ontology (BDDO): while BDDO describes a field as a contiguous block of bytes, DLV explains how to interpret that block as a multi-dimensional grid by specifying the order, size, and semantic meaning of its dimensions. This is essential for scientific, geospatial, and complex media formats.

This document is an unofficial draft produced for the purpose of defining the Hexplain standard. It has no official standing and is not endorsed by any standards body.

Introduction

Many advanced formats (HDF5, NetCDF, GeoTIFF) store data as n-dimensional arrays or "data cubes." A field described merely as a sequence of bytes is insufficient to locate a specific data point. DLV answers: how many dimensions, what cell data type, what size and meaning per dimension, and in what order the data is stored.

A bddo:Field containing multi-dimensional data is linked to a dlv:DataLayout via hexplain:hasDataLayout (defined in Hexplain Core).

Conformance

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [[RFC2119]].

Core Concepts

dlv:DataLayout
Describes the overall layout of a multi-dimensional array. Attached to a bddo:Field via hexplain:hasDataLayout.
dlv:Dimension
One dimension of the array (e.g. width, height, bands).
dlv:Axis
A semantic descriptor for a dimension. DLV provides common axes; domain vocabularies define specialized ones.

Properties

hexplain:hasDataLayout
Defined in Hexplain Core; links a bddo:Field to a dlv:DataLayout.
dlv:hasDimension
Links a dlv:DataLayout to an ordered rdf:List of its dlv:Dimension instances. The order is normative and defines the data-sequencing rule (interleaving): from the slowest-varying (outermost loop) to the fastest-varying (innermost loop) dimension.
  • Band Sequential (BSQ): (Band, Row, Column).
  • Pixel Interleaved (BIP): (Row, Column, Band).
  • Band Interleaved by Line (BIL): (Row, Band, Column).
dlv:cellDataType
The data type of each cell. Value MUST be a bddo:DataType.
dlv:dimensionSize / dlv:dimensionSizeFromField
The length of a dlv:Dimension: a fixed xsd:positiveInteger, or read from a bddo:Field. Exactly one MUST be present.
dlv:dimensionStride
Bytes to advance per step along a dimension (pitch). Optional; when absent, addressing is contiguous. Use for padded/aligned rows, e.g. BMP's 4-byte row padding.
dlv:hasAxis
Links a dlv:Dimension to its semantic dlv:Axis.
dlv:chunkSize / dlv:chunkSizeFromField
Extent of one chunk (tile/block) along this dimension, in cells. Declaring either on any dimension makes the layout chunked.
dlv:chunkOffsetsFromField / dlv:chunkLengthsFromField
The repeating fields holding each chunk's byte offset and length — TIFF's TileOffsets/TileByteCounts, NITF's block offsets.
dlv:chunkOrder / dlv:chunkOffsetBase
Traversal order of the chunk table (default dlv:rowMajor) and what its offsets are relative to (default bddo:streamStart).

# SHACL shapes
dlv:DataLayoutShape a sh:NodeShape ;
    sh:targetClass dlv:DataLayout ;
    sh:property [ sh:path dlv:hasDimension ; sh:minCount 1 ; sh:maxCount 1 ; sh:nodeKind sh:BlankNodeOrIRI ] ;
    sh:property [ sh:path ( dlv:hasDimension [ sh:zeroOrMorePath rdf:rest ] rdf:first ) ; sh:class dlv:Dimension ] ;
    sh:property [ sh:path dlv:cellDataType ; sh:class bddo:DataType ; sh:minCount 1 ; sh:maxCount 1 ] .

dlv:DimensionShape a sh:NodeShape ;
    sh:targetClass dlv:Dimension ;
    sh:xone (
        [ sh:property [ sh:path dlv:dimensionSize ; sh:minCount 1 ] ;
          sh:property [ sh:path dlv:dimensionSizeFromField ; sh:maxCount 0 ] ]
        [ sh:property [ sh:path dlv:dimensionSizeFromField ; sh:minCount 1 ] ;
          sh:property [ sh:path dlv:dimensionSize ; sh:maxCount 0 ] ]
    ) ;
    sh:property [ sh:path dlv:dimensionSize ; sh:minExclusive 0 ; sh:maxCount 1 ] ;
    sh:property [ sh:path dlv:dimensionSizeFromField ; sh:class bddo:Field ; sh:maxCount 1 ] ;
    sh:property [ sh:path dlv:dimensionStride ; sh:minExclusive 0 ; sh:maxCount 1 ] ;
    sh:property [ sh:path dlv:hasAxis ; sh:nodeKind sh:IRI ; sh:class dlv:Axis ; sh:minCount 1 ; sh:maxCount 1 ] ;
    sh:property [ sh:path dlv:chunkSize ; sh:minExclusive 0 ; sh:maxCount 1 ] ;
    sh:property [ sh:path dlv:chunkSizeFromField ; sh:class bddo:Field ; sh:maxCount 1 ] .

dlv:_prefixes sh:declare
    [ sh:prefix "dlv" ; sh:namespace "https://hexplain.io/ns/dlv#"^^xsd:anyURI ] ,
    [ sh:prefix "rdf" ; sh:namespace "http://www.w3.org/1999/02/22-rdf-syntax-ns#"^^xsd:anyURI ] .

# A chunked layout must say where its chunks are.
dlv:ChunkedLayoutShape a sh:NodeShape ;
    sh:targetClass dlv:DataLayout ;
    sh:property [ sh:path dlv:chunkOffsetsFromField ; sh:class bddo:Field ; sh:maxCount 1 ] ;
    sh:property [ sh:path dlv:chunkLengthsFromField ; sh:class bddo:Field ; sh:maxCount 1 ] ;
    sh:property [ sh:path dlv:chunkOffsetBase ; sh:maxCount 1 ;
        sh:in ( bddo:streamStart bddo:streamEnd bddo:parentStart bddo:currentPosition ) ] ;
    sh:property [ sh:path dlv:chunkOrder ; sh:maxCount 1 ; sh:class dlv:ChunkOrder ] ;
    sh:sparql [ sh:message "A chunked dlv:DataLayout (any Dimension declaring dlv:chunkSize or dlv:chunkSizeFromField) must declare dlv:chunkOffsetsFromField." ;
        sh:prefixes dlv:_prefixes ;
        sh:select """SELECT $this WHERE {
            $this dlv:hasDimension/rdf:rest*/rdf:first ?d .
            { ?d dlv:chunkSize ?c } UNION { ?d dlv:chunkSizeFromField ?c }
            FILTER NOT EXISTS { $this dlv:chunkOffsetsFromField ?o }
        }""" ] .

Example: Describing a BIL Image

A Band Interleaved by Line (BIL) image is a 3-D cube where all bands of the first row are written, then all bands of the second row, and so on.

@prefix bddo:     <https://hexplain.io/ns/bddo#> .
@prefix hexplain: <https://hexplain.io/ns/core#> .
@prefix dlv:      <https://hexplain.io/ns/dlv#> .
@prefix myformat: <https://hexplain.io/formats/myformat#> .

myformat:ImageFile a bddo:Struct ;
    bddo:hasField ( myformat:Width myformat:Height myformat:NumBands myformat:PixelData ) .

myformat:Width    a bddo:Field ; bddo:dataType bddo:uint32le .
myformat:Height   a bddo:Field ; bddo:dataType bddo:uint32le .
myformat:NumBands a bddo:Field ; bddo:dataType bddo:uint32le .

myformat:PixelData a bddo:Field ;
    bddo:dataType bddo:bytes ;
    bddo:sizeFromExpression "instance.parent.Width * instance.parent.Height * instance.parent.NumBands" ;
    hexplain:hasDataLayout myformat:BIL_Layout .

myformat:BIL_Layout a dlv:DataLayout ;
    dlv:cellDataType bddo:uint8 ;
    # Row (slowest) -> Band -> Column (fastest) == BIL.
    dlv:hasDimension ( myformat:HeightDimension myformat:BandDimension myformat:WidthDimension ) .

myformat:HeightDimension a dlv:Dimension ; dlv:hasAxis dlv:axisY ; dlv:dimensionSizeFromField myformat:Height .
myformat:WidthDimension  a dlv:Dimension ; dlv:hasAxis dlv:axisX ; dlv:dimensionSizeFromField myformat:Width .
myformat:BandDimension   a dlv:Dimension ; dlv:hasAxis dlv:axisBand ; dlv:dimensionSizeFromField myformat:NumBands .
