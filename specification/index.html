Hexplain is a declarative, semantic framework for describing binary data formats. It provides a family of modular ontologies that allow for the creation of rich, machine-understandable descriptions of physical file structures and their conceptual meaning. By leveraging established web standards such as RDF, OWL, SHACL, and JSON-LD, Hexplain aims to make opaque binary data a first-class citizen in the world of linked data, enabling robust validation, interoperability, and semantic querying across disparate formats.

This document is an unofficial draft produced for the purpose of defining the Hexplain standard. It has no official standing and is not endorsed by any standards body.

Introduction

The Problem: The Dark Matter of Data

A vast amount of the world's digital information is stored in binary formats. From scientific datasets and satellite imagery to multimedia files and network packets, this data is often treated as "dark matter"—it is opaque, difficult to parse without specialized software, and its internal meaning is locked away in proprietary or poorly-documented specifications. This lack of a universal, machine-readable description leads to significant challenges in data interoperability, long-term preservation, validation, and large-scale analysis.

The Hexplain Approach: A Layered, Semantic Framework

Hexplain addresses this problem by providing a layered, modular framework for describing binary data. Instead of a single, monolithic specification, Hexplain separates concerns into a family of interoperable ontologies.

The core principle is to distinguish between three fundamental layers of description:

  1. The Physical Layer: Describes the sequence, structure, and data types of the bytes in the file.
  2. The Layout Layer: Describes the organization of multi-dimensional data within a flat byte stream.
  3. The Semantic Layer: Describes the conceptual meaning of the data.

By modeling these layers with formal ontologies, Hexplain makes it possible to create descriptions that are not just instructions for a parser, but rich, queryable knowledge graphs. A Hexplain-compliant tool can parse a binary file and its corresponding description to generate a formal RDF graph, following the normative Processing Model. This graph represents the file's contents in a structured, interconnected, and semantically-rich way, making the data's meaning explicit and machine-actionable.

The Hexplain Ontology Family

Hexplain is composed of several modular specifications, each with its own detailed document.

Foundation

BDDO (Binary Data Description Ontology)
The foundational physical layer. Vocabulary for sequential and offset-based structures, fields, primitive data types, endianness, bit-level fields, arrays, enumerations, checksums, and control flow (conditionals, loops, synchronization markers).
Hexplain Core
The "glue" connecting the layers. Provides the mapping properties (hexplain:mapsToClass, hexplain:mapsToProperty, hexplain:hasDataLayout, hexplain:isEncodedWith) that link a physical structure to its semantic meaning and multi-dimensional layout.
DLV (Data Layout Vocabulary)
Describes the layout of multi-dimensional data arrays: dimensions, axes, and interleaving order (BIL, BIP, BSQ), essential for scientific and geospatial raster data.
HEL (Hexplain Expression Language)
The small declarative language for conditions and calculations (dynamic sizing, presence, counts, offsets, and dispatch) used throughout Hexplain descriptions.
HDL (Hexplain Description Language)
The concise authoring language for format descriptions. A compact text surface (.hx) and an isomorphic YAML surface compile to the canonical BDDO/Core/DLV/hx-bundle Turtle, so authors write descriptions instead of raw RDF.
Processing Model
The normative execution model: how a conforming processor turns a binary stream plus a Hexplain description into an RDF instance graph, including IRI minting and value mapping.

Domain Vocabularies

Semantic vocabularies providing conceptual terms for specific domains, ensuring interoperability across different file formats within a domain.

  • IDV (Image Vocabulary): pixel width, colour space, compression.
  • VDV (Video Vocabulary): frame rate, codec, resolution, duration.
  • ADV (Audio Vocabulary): sample rate, bit depth, artist, album.
  • GV (Geospatial Vocabulary): coordinate systems, projections, sensor models.
  • DFV (Document & Font Vocabulary): page count, author, font family.
  • NPV (Network Protocol Vocabulary): source address, destination port.
  • AXV (Archive Vocabulary): file name, checksum, modification time.

Aspect Layer

Cross-cutting concerns that belong to no single domain are defined once as orthogonal aspect ontologies and imported by the domains that exhibit them, so each term (a codec, a colour space, a duration) has exactly one IRI everywhere. A format is then a composition — it imports the aspects it has and adds only its genuinely-unique terms. The established aspects (see the architecture document for the full catalogue, tiers, and rationale):

  • Base: hx-sampling (asamp), hx-color (acolor).
  • Content representation: hx-raster (araster), hx-geometry (ageom), hx-pointcloud (apc), hx-tabular (atab), hx-signal (asig).
  • Signal & encoding: hx-encoding (aenc; codec + compression registers), hx-integrity (aintg).
  • Reference frames: hx-time (atime), hx-spatialref (asref).
  • Governance: hx-provenance (aprov), hx-security (asec); descriptive metadata reuses Dublin Core directly.
  • Container & system: hx-packaging (apkg), hx-fsmeta (afs), hx-networkflow (anet).

Benefits of the Hexplain Approach

  • Interoperability: By mapping format-specific fields to a common semantic vocabulary, Hexplain allows querying and analysis across different file formats, creating a unified view of the data. Domain vocabularies additionally align (via skos:closeMatch/owl:equivalentProperty) to established standards such as Dublin Core, the W3C Ontology for Media Resources, SOSA/SSN, and GeoSPARQL.
  • Formal Validation: Hexplain descriptions can be validated using SHACL, ensuring the descriptions themselves are correct. Rules and constraints within a description (fixed values, checksums) can further validate the integrity of the binary data itself.
  • Semantic Querying: Once parsed, the data becomes part of a knowledge graph, enabling powerful SPARQL queries such as "all images with a width greater than 4000 pixels" without knowing the location or data type of the width field in a PNG versus a JPEG.
  • Long-Term Preservation: A formal Hexplain description is enduring, machine-readable documentation — a self-contained digital artifact that guarantees data can be understood long after its authoring software is obsolete.
  • Extensibility: The modular design lets experts create new domain vocabularies and profiles for specialized formats without altering the core standard.

Profiles: Extending Hexplain for Specific Formats

While domain vocabularies provide general concepts, many formats have unique features. Hexplain handles this through Profiles: a specialized ontology that extends the core vocabularies to describe a single, specific format.

For example, a PDF Profile would define PDF-specific classes like pdf:Object, pdf:Stream, and pdf:CrossReferenceTable, then map them to the more general concepts in DFV (e.g. mapping a PDF /Author entry to dcterms:creator, which hx-docfont reuses rather than re-minting). Similarly, a GeoTIFF Profile would define TIFF tags and GeoKeys — using BDDO's offset-based addressing (bddo:atOffsetFromField) for the IFD structure — and map them to GV and IDV.

The Hexplain Tool Ecosystem

The formal, machine-readable nature of Hexplain descriptions — made executable by the Processing Model — enables a powerful tool ecosystem.

Parser & Codec Generators
Generate high-performance parser and writer source code (Python, C++, Rust) directly from a Hexplain description, eliminating manual, error-prone implementation.
Conformance Test Suites
Use a description as "ground truth" to validate a corpus of binary files for structural integrity, correct values, and adherence to conditional logic.
Semantic Query Engines
Ingest heterogeneous binary files plus their descriptions into a unified knowledge graph, then run high-level SPARQL queries across the whole dataset.
Semantic Hex Editors & Visualizers
Display a structured, hierarchical, semantically-named view of a binary file instead of a raw wall of bytes.
Data Transformation & Conversion Tools
Use two descriptions (source and target) and their shared semantic mappings to convert data between formats while preserving meaning.

Use Case Scenarios

Geointelligence Analysis

An intelligence agency has a massive archive of satellite imagery in various formats (GeoTIFF, NITF, HDF5). Using Hexplain, they create descriptions for each, all mapping to the Geospatial Vocabulary (GV). An analyst runs a single SPARQL query: "Find all datasets from the 'WorldView-3' platform (aprov:platformName) collected after January 1, 2024 (aprov:acquisitionTime) that contain a Lidar point cloud (gv:PointCloud)."

Digital Forensics

An investigator analyzes a raw disk image with a Hexplain-powered tool. It uses bddo:syncOnMarker from each description to scan for file signatures, then parses each file, validates integrity using declared bddo:Checksums, and extracts key metadata (dcterms:created, EXIF camera model). This automates file carving and metadata extraction.

Broadcast Media Management

A television network parses all incoming video files (MXF, MOV) using their Hexplain descriptions, mapping technical metadata to the Video Vocabulary (VDV). An automated workflow queries the graph for QC: "Flag all files where vdv:frameRate is not 29.97 fps or vdv:audioChannels is not 2."

Format Conformance and Validation

A standards body releasing "FormatX 2.0" publishes an official Hexplain Profile. Developers use it as a definitive, machine-readable reference and build a conformance test suite that validates a corpus of sample files against the description — replacing ambiguous textual specifications with a formal, testable artifact.
