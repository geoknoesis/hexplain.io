P1 · Reproduced defect

GeoPackage geometry registration can disagree with decoded features

Trigger/evidence: Change the pinned XYZ LINESTRING fixture registration to POINT with z=0 and m=0. The decoder still returns both XYZ lines.

Impact: Consumers cannot rely on the declared geometry schema; source metadata and returned values contradict one another without a diagnostic.

Required change: Read geometry_type_name, z and m; enforce permitted geometry subtype/dimensions for every non-null geometry. Validate registered SRS consistency. Add positive generic-GEOMETRY and negative type/dimension cases.

P2 · Reproduced defect

A missing registered geometry column is silently accepted

Trigger/evidence: Register absent_geom against a table containing only id. geoPackage returns a successful GeoPackageFeatures with no geometry values.

Impact: The explicit one-geometry-column contract is not enforced; malformed database metadata looks like a successfully decoded feature table.

Required change: Check the selected schema contains exactly the registered geometry column before reading rows, including empty tables. Reject missing/mismatched columns before returning success.

core/src/main/kotlin/io/hexplain/core/raster/TabularDecoder.kt:37 · Format specification

P2 · Reproduced defect

Zarr version validation truncates fractional numbers

Trigger/evidence: An otherwise ordinary one-cell array with zarr_format=2.5 decodes value 42 successfully.

Impact: Invalid metadata is admitted as version 2. This repeats the numeric narrowing problem previously fixed elsewhere in the engine.

Required change: Require a JSON number representing an exact integer equal to 2, before any narrowing. Test fractions, strings, booleans, huge exponents and valid 2.

core/src/main/kotlin/io/hexplain/core/raster/ZarrRasterDecoder.kt:30 · Format specification

P2 · Reproduced defect

Polygon closure compares signed-zero representations instead of coordinates

Trigger/evidence: A triangular WKB ring begins at (+0,0) and closes at (-0,0). Hexplain reports Unclosed polygon ring; Shapely reports the same ring valid and closed.

Impact: A numerically closed geometry is rejected because Kotlin list equality distinguishes boxed Double signed zeros.

Required change: Compare ordinates numerically after nonfinite validation; preserve source coordinates. Add both signed-zero closure cases and a genuinely unclosed control.

P1 before hosted exposure · Known operational gap

Collected-byte limits do not bound native or geometry memory

Trigger/evidence: HDF metadata/dataFlat and JDBC values may allocate before adapter accounting; GeoPackage geometry allocation is additional to raw blob accounting.

Impact: The published 64 MiB limits are not a process-memory guarantee. No exploit or production exposure is claimed: the adapters are currently offline.

Required change: Use an optional adapter module and a worker with OS-enforced memory/time limits; add aggregate geometry budgets and native allocation stress tests before connecting uploads.

P2 · Known interoperability gap

Storage-order decoding does not establish geospatial semantic parity

Trigger/evidence: NetCDF lacks CF/record handling, HDF-EOS axis mapping rejects, and transform/mask helpers do not extract metadata from files.

Impact: 611 pixel matches cannot be interpreted as coordinate, CRS, nodata, alpha or mask equivalence. Companion references are valuable but do not replace the missing GDAL comparisons.

Required change: Run selected-variable and feature comparisons against a functioning pinned GDAL runtime; compare complete values, geometry ordinates, axis mapping, geotransforms and masks independently.

P2 · Architecture gap

Offline native adapters become dependencies of every core consumer

Trigger/evidence: jHDF, SQLite JDBC and DuckDB JDBC are implementation dependencies in core/build.gradle.kts, despite not being exposed through hosted decoding.

Impact: All consumers inherit native packaging/platform and update obligations even when they need only the native parser or compiler.

Required change: Move library-backed adapters and their probes into an optional module with an explicit capability boundary; keep native codecs independently usable.

Verified strengths and evidence limits

611 GDAL pixel matches remain recorded: 29 new Zarr entry points and 12 HDF5 files. Matching evidence contains 359 distinct input identities and 176 distinct raster outputs. The 20 new cases and companion-library goldens improve confidence without being counted as GDAL vector passes.

579 core + 223 HDL + 68 SaaS tests passed in the preceding implementation pass. This review ran dedicated observations and rechecked evidence; it did not rerun all 870 tests. The four observation flags mean defects reproduced, not acceptance tests passed. Production code is unchanged.

The earlier signed-24-bit explanation is sound: retain signed SampleFormat semantics and the explicitly excluded datatype mismatch. The 11 TIFF and four HDF rejections remain gaps, not successes. This review did not retry Docker or establish a new GDAL runtime result.

Before a 9.5 assessment is justified

  1. Fix all four reproduced defects and add positive/negative acceptance tests.
  2. Demonstrate GDAL variable, geometry, georeferencing and mask comparisons with pinned inputs and runtime.
  3. Prove resource bounds across native decoding and geometry construction, and isolate optional native dependencies.
  4. Expand scientific/point-cloud/columnar variants and adversarial/fuzz coverage; rerun the integration suite and regenerate evidence.

These are acceptance criteria, not a promise that a certain test count earns 9.5.
