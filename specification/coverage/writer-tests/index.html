Engine writer layout contract

This page documents the tested JVM implementation. It does not add ontology axioms or claim that every construct expressible in Hexplain has a symmetric writer.

Choosing a file boundary

// When the profile does not otherwise establish the whole-file size:
val bytes = Metawriter(format).write(data, outputSize = 4096)

// A profile with a fixed root region can supply the boundary itself:
val bytes = Metawriter(format).write(data)

stream.length denotes the whole-file size. STREAM_END offsets use the currently active region end, which may be inside that file. The writer requires a known boundary for end-relative placement instead of guessing an unconstrained file size.

How length resolution works

Each pass writes the supplied values at their actual addresses and measures their extents. Inferred lengths are associated with individual struct occurrences, then used in the next pass. Only a stable result with all bounds, overlap, count and termination checks satisfied is returned. Shared length fields require equal measured payload extents. The length field must precede its payload in logical read order, although a pointer can place it later in the physical file.

A fixed size is a constraint. A local ordinary integer referenced by sizeFromField is inferred, replacing its supplied seed value in output without mutating the caller's map. Expression constraints can depend on other lengths; arbitrary expressions are not algebraically inverted. Cyclic, unresolvable or nonconverging dependencies fail.

Encoded address spaces

An encoded field's size counts compressed bytes; its nested struct size counts decoded bytes. Addresses inside that struct start at zero, and a fixed nested size supplies the decoded stream.length. The outer file's bounds and cursor resume after the block. Explicit compressed extents must match exactly. Counted encoded blocks require per-element sizes; EOF/sentinel sequences can be placed inside one encoded struct. Output is canonical re-encoding of the supplied structured values, without preservation of the original compressed bytes or unmodeled padding.

Limits and compatibility

Defaults are 256 MiB output, one million node visits, depth 64, 32 layout passes and a cooperative 30-second deadline shared across passes. Distinct stream materializations are capped at twice the output limit. Decoded buffers and every codec output stage are capped by the output limit; stage checks run after a codec returns. These are not a hard aggregate heap limit or preemptive deadline for a custom codec or flow. Delimited containers, encoded struct repeat-until arrays, automatic partial-bit payload lengths and terminator-inclusive inferred lengths remain unsupported.

The reader now enforces single nested-field regions and treats a scalar sequence's size as its region extent. Fractional or overflowing offsets fail instead of being narrowed. Encoded struct repeat-until arrays now explicitly reject because the previous reader branch bypassed decoding. Consumers relying on ignored bounds, truncation or ignored encoding must correct their descriptions.

The review's final verification logs record the complete JVM run, fresh corpus comparison and the status of independent encoder checks. Existing PNG, TIFF and Shapefile round trips remain required.
